## 1. 问题概述

### 1.1 问题现象

按照 PRD 文档（`docs/features/250201-官方与非官方资源搜索独立-PRD.md`）修订代码后，应用无法正常使用，主要表现：

1. **登录主页前端控制台报错**：页面一直在加载，无法正常显示内容
2. **其他页面也报错无法使用**：整个应用基本无法使用

### 1.2 错误信息

**主要错误**：

```
Uncaught ReferenceError: exports is not defined
    at eval (runtime.js:5:23)
    at eval (<anonymous>)
    at window.eval (userscript.html?name=API%25E5%258F%2582%25E6%2595%25B0%25E5%2588%2586%25E6%259E%2590%25E5%25B7%25A5%25E5%2585%25B7-%25E5%25A2%259E%25E5%25BC%25BA%25E5%258F%258D%25E8%25B0%2583%25E8%25AF%2595%25E7%2589%2588.user.js&id=a151b99b-eac1-4fde-a1e6-fa4d1fe4a312:66:33)
    at (:51000/app-pages-browser)/node_modules/.pnpm/next@16.1.1_@babel+core@7.2_11c587b177eb7734f098c06662fd45e9/node_modules/next/dist/compiled/@next/react-refresh-utils/dist/runtime.js
```

**错误堆栈分析**：

- 错误发生在 `runtime.js:5:23`
- 通过 `window.eval` 被调用（来自 Tampermonkey userscript）
- 涉及到 Next.js 的 `react-refresh-utils` 和 webpack 打包输出
- 错误发生在浏览器环境中，而非服务端

### 1.3 影响范围

- ✅ **前端页面**：所有页面无法正常加载
- ✅ **搜索功能**：无法使用
- ✅ **播放功能**：无法使用
- ⚠️ **后端 API**：可能正常（需要验证）

## 2. 问题分析

### 2.1 根本原因

**问题类型**：模块系统兼容性问题（CommonJS vs ES Module）

**原因分析**：

1. **Next.js 16 模块系统变更**：

   - Next.js 16 默认使用 ES Module (ESM) 系统
   - 某些依赖或代码可能仍使用 CommonJS 格式（`exports` 对象）
   - 在浏览器环境中，CommonJS 的 `exports` 对象未定义

2. **Webpack 配置不完整**：

   - `next.config.js` 中已有部分修复代码（第 63-69 行），但可能不够完善
   - 需要更完善的 webpack 配置来处理 CommonJS 模块

3. **Tampermonkey Userscript 干扰**：

   - 错误堆栈显示通过 `window.eval` 调用，可能来自 Tampermonkey userscript
   - Userscript 可能干扰了正常的模块加载流程

4. **React Refresh Runtime 问题**：
   - 错误发生在 Next.js 的 `react-refresh-utils` 中
   - 可能是 webpack 打包时未正确处理 CommonJS 模块

### 2.2 相关文件检查

**已检查的文件**：

1. ✅ `next.config.js`：

   - 已有部分修复代码（第 63-69 行）：设置 `globalObject: 'self'`
   - 但可能不够完善

2. ✅ `tsconfig.json`：

   - `module: "Node16"`，`moduleResolution: "node16"`
   - 配置可能过于严格，导致模块解析问题

3. ✅ `src/lib/search-independent.ts`：

   - 使用 ES Module 语法（`export`），无问题

4. ✅ `src/app/api/search/stream/route.ts`：

   - 使用 ES Module 语法，无问题

5. ✅ `src/app/api/parse/route.ts`：

   - 使用 ES Module 语法，无问题

6. ✅ `src/lib/runtime.ts`：
   - 使用 ES Module 语法，无问题

**可能的问题点**：

1. ⚠️ **Webpack 配置**：需要更完善的 CommonJS 处理
2. ⚠️ **TypeScript 配置**：`module: "Node16"` 可能过于严格
3. ⚠️ **依赖包**：某些第三方依赖可能使用 CommonJS

## 3. 解决方案

### 3.1 方案一：清除缓存并重新构建（优先尝试）

**步骤**：

1. **清除构建缓存**：

   ```bash
   # 删除 .next 目录
   rm -rf .next
   # Windows PowerShell:
   Remove-Item -Recurse -Force .next
   ```

2. **清除 node_modules 并重新安装**（可选）：

   ```bash
   rm -rf node_modules
   pnpm install
   ```

3. **重新启动开发服务器**：

   ```bash
   pnpm dev
   ```

4. **清除浏览器缓存**：
   - 打开浏览器开发者工具（F12）
   - 右键点击刷新按钮，选择"清空缓存并硬性重新加载"

**预期结果**：如果问题消失，说明是缓存问题。

### 3.2 方案二：禁用 Tampermonkey Userscript（排查干扰）

**步骤**：

1. **禁用 Tampermonkey**：

   - 在浏览器中禁用 Tampermonkey 扩展
   - 或禁用相关的 userscript（API 参数分析工具）

2. **清除浏览器缓存并刷新页面**

3. **测试是否问题消失**

**预期结果**：如果问题消失，说明 userscript 干扰了模块加载。

### 3.3 方案三：检查 Next.js 版本兼容性

**问题**：Next.js 16.1.1 可能存在已知问题。

**步骤**：

1. **检查 Next.js 版本**：

   ```bash
   pnpm list next
   ```

2. **查看是否有已知问题**：

   - 检查 Next.js GitHub Issues
   - 查看是否有相关修复

3. **考虑降级或升级**（谨慎操作）：
   ```bash
   # 降级到稳定版本（不推荐，除非确认问题）
   pnpm add next@16.0.0
   ```

### 3.4 方案四：完善 Webpack 配置（如果以上方案无效）

**修改文件**：`next.config.js`

**当前配置**（已更新）：

- 已设置 `globalObject: 'self'`
- 如果问题仍然存在，可能需要更深入的 webpack 配置

**注意事项**：

- Next.js 16 的 webpack 配置可能已经足够
- 问题可能不在 webpack 配置，而在其他方面

### 3.2 方案二：修改 TypeScript 配置（备选）

**修改文件**：`tsconfig.json`

**修改内容**：

```json
{
  "compilerOptions": {
    // 将 module 从 "Node16" 改为 "ESNext" 或 "ES2020"
    "module": "ESNext",
    "moduleResolution": "bundler" // 或 "node"
    // ... 其他配置保持不变
  }
}
```

**风险**：

- 可能影响其他模块的解析
- 需要全面测试

### 3.3 方案三：禁用或调整 Tampermonkey Userscript（临时）

**临时解决方案**：

- 禁用 Tampermonkey userscript，测试是否解决问题
- 如果问题消失，说明 userscript 干扰了模块加载

### 3.4 方案四：使用 next-transpile-modules（如果问题来自第三方依赖）

**如果问题来自第三方依赖**：

1. 安装 `next-transpile-modules`：

   ```bash
   pnpm add -D next-transpile-modules
   ```

2. 修改 `next.config.js`：
   ```javascript
   const withTM = require('next-transpile-modules')(['problematic-module']);
   module.exports = withTM(nextConfig);
   ```
