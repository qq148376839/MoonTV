- **文档版本**：v1.1

- **最后更新**：2025-02-01
- **文档作者**：AI Product Manager

## 1. 背景与目标

### 1.1 业务背景

当前系统支持从多个 API 站点聚合搜索视频资源，搜索功能已迁移到 Cloudflare Workers。同时，系统支持官方解析资源的播放解密功能（2025-01-25 实现）。

**现状问题**：

- 搜索功能统一从 `config.json` 配置的 API 站点获取数据，未区分官方资源和非官方资源
- 官方资源播放时使用旧的解密 API（AES-CBC 解密），需要更简单高效的解析方案
- 用户无法明确区分哪些资源来自官方源，哪些来自非官方源
- **重要变更**：不再使用 `config.json` 配置搜索源，改为使用环境变量配置的官方和非官方资源搜索接口

### 1.2 用户痛点

- **痛点 1**：搜索时无法区分官方资源和非官方资源，用户体验不清晰
- **痛点 2**：官方资源解析流程复杂（AES-CBC 解密），解析速度慢
- **痛点 3**：需要统一的搜索入口，但数据来源应该独立管理

### 1.3 业务目标

- **主要目标**：将官方资源和非官方资源的搜索功能独立，使用不同的搜索接口
- **次要目标**：优化官方资源解析流程，使用新的解析 API 提升解析速度和成功率
- **成功指标**：
  - 搜索功能正常分离，官方和非官方资源独立获取
  - 前端搜索结果合并展示，用户体验一致
  - 官方资源解析成功率 ≥ 95%
  - 解析耗时 ≤ 3 秒（相比旧方案提升 40%）

### 1.4 项目范围

- **包含范围**：
  - 官方资源搜索接口集成（通过环境变量 `NEXT_PUBLIC_OFFICIAL_SEARCH_URL` 配置）
  - 非官方资源搜索接口集成（通过环境变量 `NEXT_PUBLIC_UNOFFICIAL_SEARCH_URL` 配置）
  - 环境变量配置（新增两个搜索接口的配置项）
  - **禁用 config.json 搜索源**：不再使用 `config.json` 中的 `SourceConfig` 进行搜索
  - 搜索结果合并逻辑（前端统一展示）
  - 官方资源新解析 API 集成（`https://gfjx.riowang.win/api/v1/parse?url=`）
  - 播放流程更新（使用新解析 API，移除旧解密 API）
  - 资源类型标识（官方/非官方）
  - 去广告逻辑区分（官方资源不去广告，非官方资源去广告）
- **不包含范围**：
  - 旧解密 API 的保留（完全移除）
  - `config.json` 中搜索源的保留（搜索功能中完全禁用）
  - 搜索结果的去重逻辑优化（后续迭代）
  - 搜索性能优化（后续迭代）

## 2. 用户与场景

### 2.1 目标用户

- **主要用户**：所有使用 MoonTV 的用户
- **用户特征**：需要观看视频，对搜索结果的完整性和播放流畅性要求高

### 2.2 使用场景

**场景 1：搜索视频资源**

- **用户**：普通用户
- **时间**：任意时间
- **地点**：任意地点
- **行为**：
  1. 用户在搜索框输入关键词
  2. 系统同时调用官方资源搜索接口和非官方资源搜索接口（**不再调用 config.json 中的搜索源**）
  3. 系统合并两个接口的搜索结果
  4. 前端统一展示合并后的搜索结果（用户无感知）
- **目标**：用户看到完整的搜索结果，包含官方和非官方资源
- **重要说明**：搜索功能仅使用两个接口，不再使用 `config.json` 中配置的多个 API 站点

**场景 2：播放官方资源**

- **用户**：普通用户
- **时间**：播放视频时
- **地点**：任意地点
- **行为**：
  1. 用户点击播放官方资源
  2. 系统检测到是官方资源，调用新解析 API
  3. 解析 API 返回 m3u8_url
  4. 如果 m3u8_url 为空，显示解析失败提示
  5. 如果 m3u8_url 有效，播放器开始播放
- **目标**：官方资源快速解析并播放，解析失败时给出清晰提示

**场景 3：播放非官方资源**

- **用户**：普通用户
- **时间**：播放视频时
- **地点**：任意地点
- **行为**：
  1. 用户点击播放非官方资源
  2. 系统检测到是非官方资源，使用原有播放流程
  3. 系统自动应用 M3U8 广告清理（去广告）
  4. 播放器播放清理后的 m3u8 文件
- **目标**：非官方资源播放流程保持不变，自动去广告，用户体验一致

### 2.3 用户故事

- As a 用户, I want 搜索时能看到官方和非官方资源, So that 我有更多选择
- As a 用户, I want 官方资源能快速解析并播放, So that 我能流畅观看视频
- As a 用户, I want 解析失败时看到清晰的错误提示, So that 我知道发生了什么问题

#### 功能 1：官方资源搜索接口集成

**优先级**：P0

**功能描述**：
集成官方资源搜索接口，从 `https://789jx.riowang.win/?q={资源名称}` 获取搜索结果。

**接口规范**：

```
GET https://789jx.riowang.win/?q={资源名称}
```

**请求参数**：

- `q`：资源名称（URL 编码）

**环境变量配置**：

- 新增环境变量：`NEXT_PUBLIC_OFFICIAL_SEARCH_URL`
- 默认值：`https://789jx.riowang.win`
- 配置位置：`.env.local` 或部署环境变量
- **重要**：如果配置了此环境变量，将使用配置的值替换默认地址；如果未配置，使用默认值

**响应格式**：
参考 `workers/index.ts` 的实现，接口返回标准苹果 CMS V10 API 格式：

```json
{
  "code": 1,
  "msg": "数据列表",
  "page": 1,
  "pagecount": 5,
  "limit": 20,
  "total": 100,
  "list": [
    {
      "vod_id": "12345",
      "vod_name": "影片标题",
      "vod_pic": "封面URL",
      "vod_play_url": "播放链接（非m3u8格式，需要解析）",
      "vod_class": "类型",
      "vod_year": "2024",
      "vod_content": "简介",
      "type_name": "类型名称",
      "vod_douban_id": 123456
    }
  ]
}
```

**数据转换**：
将 API 返回的数据转换为标准 `SearchResult` 格式：

```typescript
{
  id: string,              // vod_id
  title: string,           // vod_name
  poster: string,          // vod_pic
  episodes: string[],      // 从 vod_play_url 提取的播放地址（非m3u8）
  source: string,          // 固定为 "official" 或自定义标识
  source_name: string,     // "官方资源"
  class?: string,          // vod_class
  year: string,            // vod_year
  desc?: string,           // vod_content
  type_name?: string,      // type_name
  douban_id?: number,      // vod_douban_id
  source_type: "official"  // 新增：标识资源类型
}
```

**重要说明**：

- 官方资源的 `episodes` 字段包含的是需要解析的播放地址（如腾讯视频、优酷等），**不是 m3u8 格式**
- 播放时需要调用解析 API 获取真实的 m3u8 地址

**集成位置**：

- **后端**：`src/app/api/search/stream/route.ts` 或 `workers/index.ts`
- **逻辑**：在搜索流程中新增官方资源搜索分支，与现有搜索流程并行执行

**实现要点**：

- 与现有搜索流程并行执行
- 支持流式返回（SSE）
- 错误处理：接口失败时不影响非官方资源搜索
- 数据格式转换：统一转换为标准格式

**边界条件**：

- 接口超时：设置 5 秒超时
- 接口失败：记录错误日志，返回空结果
- 数据格式异常：容错处理，返回空结果
- `vod_play_url` 为空：返回空 episodes 数组

**验收标准**：

- [ ] 成功调用官方资源搜索接口
- [ ] 正确解析返回的搜索结果
- [ ] 正确提取播放地址（非 m3u8 格式）
- [ ] 正确标识资源类型为 "official"
- [ ] 接口失败时不影响其他搜索流程

#### 功能 3：搜索结果合并

**优先级**：P0

**功能描述**：
将官方资源和非官方资源的搜索结果合并，前端统一展示。

**合并逻辑**：

1. **数据来源**（**重要：不再使用 config.json 配置的搜索源**）：

   - **官方资源**：来自环境变量 `NEXT_PUBLIC_OFFICIAL_SEARCH_URL`（默认：`https://789jx.riowang.win`）
     - 搜索接口：`{NEXT_PUBLIC_OFFICIAL_SEARCH_URL}/?q={资源名称}`
   - **非官方资源**：来自环境变量 `NEXT_PUBLIC_UNOFFICIAL_SEARCH_URL`（默认：`https://ss.riowang.win`）
     - 搜索接口：`{NEXT_PUBLIC_UNOFFICIAL_SEARCH_URL}/?q={资源名称}`
   - **已禁用**：`config.json` 中配置的 API 站点搜索（`SourceConfig`）不再用于搜索功能
     - 这些配置仅用于播放时的详情获取（`/api/detail`）

2. **合并策略**：

   - **流式合并**：两个接口并行调用，实时返回结果
   - **去重策略**：参考 `workers/index.ts` 的实现，使用 `source-id` 作为唯一键去重
   - **排序策略**：保持原有排序逻辑（按源优先级、按相关性等）

3. **数据标识**：
   - 每个搜索结果必须标识资源类型（`source_type: 'official' | 'unofficial'`）
   - 用于后续播放流程判断和去广告逻辑
   - 前端可以显示资源类型标签（可选）

**实现位置**：

- **后端**：`src/app/api/search/stream/route.ts` 或 `workers/index.ts`
- **前端**：`src/app/search/page.tsx`（无需修改，自动接收合并结果）

**实现要点**：

- **仅调用两个搜索接口**：官方资源搜索接口和非官方资源搜索接口
- **禁用 config.json 搜索**：不再调用 `config.json` 中 `SourceConfig` 配置的 API 站点进行搜索
- 使用 Promise.all 或类似机制并行调用两个接口
- 流式返回时，交替发送官方和非官方资源结果
- 保持现有 SSE 格式不变
- **环境变量优先级**：如果配置了环境变量，优先使用环境变量的值；否则使用默认值

**边界条件**：

- 一个接口失败：继续返回另一个接口的结果
- 两个接口都失败：返回空结果
- 数据格式不一致：统一转换为标准格式

**验收标准**：

- [ ] 搜索结果正确合并
- [ ] 前端能正常接收和展示合并结果
- [ ] 流式返回正常工作

#### 功能 4：新解析 API 集成

**优先级**：P0

**功能描述**：
集成新的官方资源解析 API，替换旧的 AES-CBC 解密方案。

**接口规范**：

```
GET https://gfjx.riowang.win/api/v1/parse?url={视频URL}
```

**请求参数**：

- `url`：需要解析的视频 URL（URL 编码）
  - 示例：`https://v.qq.com/x/cover/mzc00200x2xo33l/l4101xix2xn.html`

**响应格式**：

**成功响应**：

```json
{
  "success": true,
  "data": {
    "m3u8_url": "http://localhost:8000/api/v1/m3u8/148b71ab92719b9f",
    "method": "paid_key",
    "parse_time": 0.191,
    "cached": true
  }
}
```

**失败响应**：

```json
{
  "success": false,
  "data": {},
  "fallback_used": false,
  "error": "2s0解析器未初始化"
}
```

**响应字段说明**：

- `success`：解析是否成功（`boolean`）
- `data.m3u8_url`：解析后的 m3u8 播放地址（`string | null`）
  - **重要**：如果为空或 `null`，表示解析失败
- `data.method`：解析方法（`string`，可选）
- `data.parse_time`：解析耗时（`number`，秒，可选）
- `data.cached`：是否使用缓存（`boolean`，可选）
- `fallback_used`：是否使用了备用方案（`boolean`，可选）
- `error`：错误信息（`string`，仅在失败时存在）

**解析失败情况**：

- `success: false`：解析失败
- `data.m3u8_url` 为空或 `null`：解析失败
- `error` 字段存在：解析失败，包含错误信息

**接口特性**：

- **无需认证**：接口不需要 API Key 或其他认证信息
- **无频率限制**：接口没有请求频率限制

**集成位置**：

- **后端**：`src/app/api/parse/route.ts`（新增）或修改现有 `/api/decrypt` 路由
- **前端**：`src/app/play/page.tsx`（修改播放流程）

**实现要点**：

- 创建新的解析 API 路由
- 调用外部解析接口
- 处理解析结果和错误情况
- 支持超时控制（5 秒）

**边界条件**：

- 接口超时：返回超时错误
- 接口失败：返回解析失败错误
- `m3u8_url` 为空：返回解析失败错误
- URL 编码：确保视频 URL 正确编码

**验收标准**：

- [ ] 成功调用新解析 API
- [ ] 正确解析返回的 m3u8_url
- [ ] 解析失败时返回正确的错误信息

#### 功能 5：播放流程更新

**优先级**：P0

**功能描述**：
更新播放流程，官方资源使用新解析 API，非官方资源保持原有流程。

**播放流程**：

```
用户点击播放
    ↓
检查资源类型（source_type）
    ├─ official?
    │   ├─ 是 → 调用新解析 API (/api/parse)
    │   │   ├─ 成功 → 使用 m3u8_url 播放（不去广告）
```

```typescript
// src/app/api/parse/route.ts
export async function GET(request: Request) {
  const { searchParams } = new URL(request.url);
  const videoUrl = searchParams.get('url');

  if (!videoUrl) {
    return Response.json(
      {
        success: false,
        data: {},
        fallback_used: false,
        error: '缺少视频 URL 参数',
      },
      { status: 400 }
    );
  }

  try {
    const parseUrl = `https://gfjx.riowang.win/api/v1/parse?url=${encodeURIComponent(
      videoUrl
    )}`;
    const response = await fetch(parseUrl, {
      signal: AbortSignal.timeout(5000), // 5秒超时
    });

    if (!response.ok) {
      return Response.json(
        {
          success: false,
          data: {},
          fallback_used: false,
          error: `解析接口返回错误: ${response.status}`,
        },
        { status: response.status }
      );
    }

    const result = await response.json();

    // 检查解析结果
    if (result.success && result.data?.m3u8_url) {
      return Response.json({
        success: true,
        data: {
          m3u8_url: result.data.m3u8_url,
          method: result.data.method,
          parse_time: result.data.parse_time,
          cached: result.data.cached,
        },
      });
    } else {
      // 解析失败：m3u8_url 为空或 success 为 false
      return Response.json(
        {
          success: false,
          data: {},
          fallback_used: result.fallback_used || false,
          error: result.error || '解析失败：无法获取播放地址',
        },
        { status: 500 }
      );
    }
  } catch (error) {
    return Response.json(
      {
        success: false,
        data: {},
        fallback_used: false,
        error: error instanceof Error ? error.message : '解析失败',
      },
      { status: 500 }
    );
  }
}
```

- **环境变量优先级**：如果配置了环境变量，使用配置的值；如果未配置，使用默认值
- **关于 workers/index.ts**：这是部署在 Cloudflare 上的独立 Worker，有自己的搜索源配置，不需要修改
