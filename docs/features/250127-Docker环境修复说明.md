# Docker 环境下载和本地播放功能修复说明

## 📋 问题描述

在 Docker 容器（NAS）环境中，下载和本地播放功能无法正常触发，从日志中看不到相关日志输出。

## 🔍 问题分析

### 1. 环境变量缺失

**问题**：

- `LOCAL_STORAGE_ENABLED` 环境变量未在 `docker-compose.yml` 中设置
- `LOCAL_STORAGE_PATH` 路径配置不正确（使用了相对路径 `./data/videos`，但 volume 挂载是 `/data/videos`）
- `NEXT_PUBLIC_BASE_URL` 未设置，导致自动下载功能无法正确调用下载 API

**影响**：

- 本地存储功能可能被禁用
- 存储路径不正确，导致文件无法正确读写
- 自动下载功能无法找到正确的 API 地址

### 2. Edge Runtime 环境变量访问问题

**问题**：

- `src/app/api/playrecords/route.ts` 使用了 `export const runtime = 'edge'`
- Edge Runtime 无法访问非 `NEXT_PUBLIC_*` 前缀的环境变量（如 `LOCAL_STORAGE_ENABLED`）
- 虽然 Dockerfile 中有 sed 命令会替换，但为了确保稳定性，应该显式设置为 `nodejs`

**影响**：

- 自动下载功能无法正确检测是否启用
- 环境变量读取失败，导致功能无法触发

### 3. BASE_URL 获取逻辑问题

**问题**：

- `playrecords/route.ts` 中的 `baseUrl` 获取逻辑在 Docker 环境中会回退到 `http://localhost:51000`（错误的端口）
- 应该使用容器内部的 `localhost:3000` 或从环境变量获取

**影响**：

- 自动下载功能调用下载 API 时使用错误的 URL，导致请求失败

## ✅ 修复方案

### 1. 修复 `docker-compose.yml`

**添加的环境变量**：

```yaml
environment:
  - LOCAL_STORAGE_ENABLED=true # 启用本地存储功能
  - LOCAL_STORAGE_PATH=/data/videos # 修正存储路径（使用绝对路径，匹配 volume 挂载）
  - NEXT_PUBLIC_BASE_URL=http://localhost:1234 # 设置基础 URL（用于客户端访问）
  - LOCAL_STORAGE_TS_CONCURRENT=5 # TS 片段并发下载数
```

**关键修改**：

- ✅ 添加 `LOCAL_STORAGE_ENABLED=true` 明确启用功能
- ✅ 将 `LOCAL_STORAGE_PATH` 从 `./data/videos` 改为 `/data/videos`（匹配 volume 挂载路径）
- ✅ 添加 `NEXT_PUBLIC_BASE_URL` 用于客户端访问
- ✅ 添加 `LOCAL_STORAGE_TS_CONCURRENT` 配置

### 2. 修复 `src/app/api/playrecords/route.ts`

**修改内容**：

1. **将 runtime 从 edge 改为 nodejs**：

```typescript
export const runtime = 'nodejs'; // 改为 nodejs，确保可以访问所有环境变量
```

2. **优化 BASE_URL 获取逻辑**：

```typescript
const baseUrl =
  process.env.NEXT_PUBLIC_BASE_URL ||
  (process.env.VERCEL_URL
    ? `https://${process.env.VERCEL_URL}`
    : process.env.DOCKER_ENV === 'true'
    ? 'http://localhost:3000' // Docker 环境使用容器内部地址
    : 'http://localhost:51000');
```

3. **增强日志输出**：

```typescript
console.log(`[PlayRecords] 下载 API 基础 URL: ${baseUrl}`, {
  NEXT_PUBLIC_BASE_URL: process.env.NEXT_PUBLIC_BASE_URL,
  VERCEL_URL: process.env.VERCEL_URL,
  DOCKER_ENV: process.env.DOCKER_ENV,
});
```

## 🔧 故障排查

### 如果仍然无法触发下载

1. **检查环境变量是否正确设置**：

```bash
docker-compose exec moontv env | grep LOCAL_STORAGE
```

2. **检查存储路径权限**：

```bash
docker-compose exec moontv ls -la /data/videos
docker-compose exec moontv touch /data/videos/.test && rm /data/videos/.test
```

3. **检查日志中是否有错误信息**：

```bash
docker-compose logs moontv | grep -E "(StorageManager|Download|PlayRecords)"
```

4. **手动测试下载 API**：

```bash
# 在容器内测试
docker-compose exec moontv curl -X POST http://localhost:3000/api/download \
  -H "Content-Type: application/json" \
  -d '{"source":"test","id":"test"}'
```

### 如果路径仍然不正确

检查 `LOCAL_STORAGE_PATH` 是否与 volume 挂载路径一致：

- Volume 挂载：`./data/videos:/data/videos`
- 环境变量：`LOCAL_STORAGE_PATH=/data/videos` ✅

## 📌 注意事项

1. **路径一致性**：

   - Volume 挂载路径：`./data/videos:/data/videos`
   - 环境变量路径：`LOCAL_STORAGE_PATH=/data/videos`
   - 两者必须匹配

2. **BASE_URL 配置**：

   - `NEXT_PUBLIC_BASE_URL` 用于客户端访问（浏览器）
   - 服务器内部调用使用 `localhost:3000`（容器内部）
   - 如果 NAS 有外部访问地址，应该设置为外部地址（如 `http://nas-ip:1234`）

3. **权限问题**：
   - 确保容器用户（nextjs）对 `/data/videos` 目录有读写权限
   - 如果权限不足，可能需要调整 volume 挂载或容器用户配置
