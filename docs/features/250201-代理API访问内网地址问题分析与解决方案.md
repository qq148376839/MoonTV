## 📋 问题描述

### 现象

- ✅ **直接访问**：`http://192.168.31.18:1233/api/v1/m3u8/4ce095b2a534a435` 可以正常播放
- ❌ **通过代理 API 访问**：`/api/proxy/m3u8?url=http://192.168.31.18:1233/api/v1/m3u8/...` 访问时失败

### 错误信息

```
Proxy error: Error: fetch failed
GET /api/proxy/m3u8?url=http%3A%2F%2F192.168.31.18%3A1233%2Fapi%2Fv1%2Fm3u8%2F... 500
```

### 背景

1. 官方解析 API 部署在同一个网络的 NAS 上（端口不同）
2. 解析 API 返回的 m3u8 地址是内网地址：`http://192.168.31.18:1233/api/v1/m3u8/...`
3. m3u8 文件中的 TS 片段地址是网络上的其他域名（不是本地）
4. 前端需要播放这个内网地址的 m3u8 文件

### 已尝试的修复

1. ✅ 将 runtime 从 `edge` 改为 `nodejs`
2. ✅ 改进错误处理，提供详细错误信息
3. ✅ 修复 origin 获取逻辑

## 🔍 问题分析

### 可能的原因

#### 1. Node.js fetch API 的限制

- **问题**：Node.js 18+ 虽然内置了 `fetch` API，但在某些环境下可能无法访问内网地址
- **原因**：
  - DNS 解析问题（虽然内网 IP 不需要 DNS，但 fetch 可能尝试 DNS 解析）
  - IPv6/IPv4 双栈问题
  - 网络接口绑定问题
  - Next.js 运行时环境的网络隔离

#### 2. Next.js 运行时环境的网络限制

- **问题**：Next.js 的 Node.js runtime 可能有网络访问限制
- **可能的原因**：
  - Docker 容器网络配置
  - 防火墙规则
  - 网络命名空间隔离
  - 进程权限问题

#### 3. 网络配置问题

- **问题**：Next.js 服务器进程可能无法访问内网地址
- **需要检查**：
  - 服务器是否与 NAS 在同一网络
  - 防火墙是否阻止了连接
  - 路由配置是否正确

#### 1. HTTP 客户端工具 (`src/lib/http-client.ts`)

```typescript
import http from 'http';
import https from 'https';
import { URL } from 'url';

export interface HttpResponse {
  status: number;
  statusText: string;
  headers: Record<string, string>;
  body: Buffer;
  ok: boolean;
}

export interface HttpRequestOptions {
  headers?: Record<string, string>;
  timeout?: number;
  method?: string;
}

/**
 * 使用 Node.js 原生 http/https 模块发送 HTTP 请求
 * 解决 fetch API 无法访问内网地址的问题
 */
export async function httpRequest(
  url: string,
  options: HttpRequestOptions = {}
): Promise<HttpResponse> {
  return new Promise((resolve, reject) => {
    const urlObj = new URL(url);
    const isHttps = urlObj.protocol === 'https:';
    const client = isHttps ? https : http;

    const port = urlObj.port ? parseInt(urlObj.port, 10) : isHttps ? 443 : 80;

    const requestOptions: http.RequestOptions = {
      hostname: urlObj.hostname,
      port: port,
      path: urlObj.pathname + urlObj.search,
      method: options.method || 'GET',
      headers: {
        'User-Agent': 'Mozilla/5.0 (Windows NT 10.0; Win64; x64) ...',
        ...options.headers,
      },
      timeout: options.timeout || 30000, // 默认30秒超时
    };

    // 对于内网 IP 地址，直接使用，避免 DNS 解析问题
    if (/^\d+\.\d+\.\d+\.\d+$/.test(urlObj.hostname)) {
      requestOptions.hostname = urlObj.hostname;
    }

    const req = client.request(requestOptions, (res) => {
      const chunks: Buffer[] = [];
      const headers: Record<string, string> = {};

      // 收集响应头
      Object.keys(res.headers).forEach((key) => {
        const value = res.headers[key];
        if (value) {
          headers[key] = Array.isArray(value) ? value.join(', ') : value;
        }
      });

      res.on('data', (chunk: Buffer) => {
        chunks.push(chunk);
      });

      res.on('end', () => {
        const body = Buffer.concat(chunks);
        const status = res.statusCode || 200;

        resolve({
          status,
          statusText: res.statusMessage || '',
          headers,
          body,
          ok: status >= 200 && status < 300,
        });
      });
    });

    req.on('error', (error: Error) => {
      // 提供更详细的错误信息，保留原始错误
      const enhancedError = new Error(
        `HTTP request failed: ${error.message} (URL: ${url.substring(0, 100)})`
      );
      (enhancedError as any).originalError = error;
      reject(enhancedError);
    });

    req.on('timeout', () => {
      req.destroy();
      reject(new Error(`Request timeout after ${requestOptions.timeout}ms`));
    });

    req.end();
  });
}

// 辅助函数
export async function httpGetText(
  url: string,
  options?: HttpRequestOptions
): Promise<string> {
  const response = await httpRequest(url, options);
  if (!response.ok) {
    throw new Error(`HTTP ${response.status}: ${response.statusText}`);
  }
  return response.body.toString('utf-8');
}

export async function httpGetBuffer(
  url: string,
  options?: HttpRequestOptions
): Promise<Buffer> {
  const response = await httpRequest(url, options);
  if (!response.ok) {
    throw new Error(`HTTP ${response.status}: ${response.statusText}`);
  }
  return response.body;
}
```

### 方案 2：直接在前端访问内网地址（如果前端和 NAS 在同一网络）

**优点**：

- 不需要代理，性能最好
- 实现简单

**缺点**：

- 可能有 CORS 问题（需要 NAS 服务器支持 CORS）
- 如果前端不在同一网络，无法访问

**实现步骤**：

1. 检测前端是否与 NAS 在同一网络
2. 如果在同一网络，直接使用内网地址
3. 如果不在同一网络，使用代理

**代码示例**：

```typescript
// 在前端检测是否可以访问内网地址
async function canAccessPrivateIP(url: string): Promise<boolean> {
  try {
    const response = await fetch(url, {
      method: 'HEAD',
      mode: 'no-cors', // 避免CORS检查
    });
    return true;
  } catch {
    return false;
  }
}
```

**适用场景**：

- 前端和 NAS 在同一网络
- NAS 服务器支持 CORS（或使用 no-cors 模式）

### 方案 3：配置反向代理（Nginx/Next.js rewrites）

**优点**：

- 不需要修改代码
- 性能好
- 可以统一处理所有内网地址

**缺点**：

- 需要配置服务器
- 需要重启服务器

**实现步骤**：

#### 3.1 使用 Next.js rewrites（推荐）

在 `next.config.js` 中添加：

```javascript
module.exports = {
  async rewrites() {
    return [
      {
        source: '/api/nas-proxy/:path*',
        destination: 'http://192.168.31.18:1233/:path*',
      },
    ];
  },
};
```

#### 3.2 使用 Nginx 反向代理

```nginx
location /api/nas-proxy/ {
    proxy_pass http://192.168.31.18:1233/;
    proxy_set_header Host $host;
    proxy_set_header X-Real-IP $remote_addr;
}
```

**适用场景**：服务器环境，可以配置反向代理

### 方案 4：使用环境变量配置 NAS 地址映射

**优点**：

- 灵活配置
- 可以区分开发和生产环境

**缺点**：

- 需要修改代码逻辑
- 需要配置环境变量

**实现步骤**：

1. 添加环境变量 `NAS_INTERNAL_IP` 和 `NAS_EXTERNAL_URL`
2. 在代理 API 中检测内网地址，如果是 NAS 地址，使用外部 URL 访问
3. 或者直接替换内网地址为外部 URL

**代码示例**：

```typescript
// 在代理API中
const nasInternalIP = process.env.NAS_INTERNAL_IP || '192.168.31.18';
const nasExternalURL = process.env.NAS_EXTERNAL_URL || 'http://nas.example.com';

if (url.includes(nasInternalIP)) {
  url = url.replace(nasInternalIP, new URL(nasExternalURL).hostname);
}
```

**适用场景**：NAS 有公网域名或可以通过其他方式访问
