# 离线下载安全重下与审计执行规格

## 目标

让每集离线下载具备可追溯、可强制重下、失败不破坏旧版本、成功后原子切换的能力，并修复片段失败仍可能被标记完成的问题。

## 范围冻结

只修改离线下载、存储元数据、下载 API、下载确认弹窗和离线资源详情相关代码及测试。不得进行无关重构、依赖升级、UI 改版、搜索/播放架构改造、生产部署或历史资源批量迁移。

## 已确认事实

- `DownloadService.createTask` 会对已完整下载剧集直接返回 completed，当前没有强制重下语义。
- `downloadTask` 会跳过 `StorageManager.isEpisodeDownloaded` 判定为完整的剧集。
- M3U8 片段下载使用 `Promise.allSettled`，单片失败仍会增加完成计数，存在不完整版本被提交的风险。
- 现有 metadata 只保存本地剧集路径，不保存原始页面地址、解析后 M3U8、过滤报告或快照。
- 历史资源使用固定 `episode_XX/` 与 `episode_XX.m3u8`；必须保持可播放。

## 存储模型

新成功下载使用：

```text
episode_01.m3u8
episode_01_generations/
  <generation_id>/
    segments/
    keys/
    source.raw.m3u8
    source.cleaned.m3u8
    report.json
```

- `episode_XX.m3u8` 是唯一播放入口。
- 新 generation 完成并验证后，先写同目录临时入口，再用原子 rename 替换正式入口。
- 正式入口替换前不得删除或修改旧版本。
- 成功切换且 metadata 更新后可清理旧 generation；历史固定目录不做批量迁移。

## 下载事务

1. 普通下载保持已下载即跳过。
2. API 接受 `force_redownload: true`；强制任务绕过已下载判断，但不得绕过同集进行中任务检查。
3. 强制重下优先使用本次资源详情中的最新地址；服务端可重新解析时优先重新解析，失败才回退已保存地址，并记录地址来源。
4. 保存原始 M3U8 快照，运行现有广告过滤器，保存清理后快照与过滤统计。
5. 下载 TS、KEY、MAP 到新 generation。任一必需文件失败、缺失或为空，整个 generation 失败。
6. 校验最终 M3U8 的全部本地引用、片段数量和文件非空后，才生成并原子切换正式入口。
7. 失败时保留旧入口和旧文件，记录失败报告并清理不完整 generation。

## 并发与恢复

- 按 `source + resourceId + episode` 建立文件锁，使用排他创建。
- 锁至少记录 task ID、PID、generation ID、开始时间。
- 成功与失败都释放锁；仅允许回收已超过合理超时且对应任务不再活动的锁。
- 不引入跨资源全局锁。

## 审计报告与隐私

每次成功 generation 的 `report.json` 至少包含：下载时间、原始页面地址、解析后 M3U8 地址、地址获取方式、过滤器版本和参数、原始/删除/最终片段数、删除时长、命中原因、快照摘要、完整性校验结果。

- 完整签名 URL 只保存在 NAS 本地审计文件中。
- API/UI 返回 URL 必须移除 query 和 fragment，禁止泄露 token 或签名。
- metadata 新字段必须可选，旧 metadata 读取不报错。

## UI

- 下载确认弹窗增加“重新抓取源并安全替换”开关或模式，发送 `force_redownload`。
- 文案说明旧版本保留到新版本验证成功，且需要临时额外空间。
- 离线详情按集展示最近成功时间、脱敏源地址、地址获取方式、原始/删除/最终片段数、删除时长、命中规则和过滤器版本。
- 无审计数据的历史资源显示“无历史记录，需重新下载生成”。

## 测试与验收

必须先补失败测试，再实现。至少证明：

1. 普通任务跳过已下载剧集，强制任务绕过该判断。
2. 同集并发任务被拒绝或复用，不会同时写入。
3. 任一 TS/KEY/MAP 失败或为空时不切换入口，旧版本保持可读。
4. 成功时入口原子切换到新 generation，报告与最终 M3U8 统计一致。
5. 历史固定目录和旧 metadata 继续工作。
6. API/UI 不暴露 URL query/fragment。
7. 下载弹窗正确发送 `force_redownload`，离线详情正确处理有/无审计记录。

运行仓库已存在的定向 Jest、TypeScript 与 lint 检查；记录命令、退出码和关键输出。不得删除或跳过测试、放宽断言、隐藏错误或修改验收口径来达标。既有无关测试若失败，必须给出基线与隔离证据。

## 完成定义

- 上述事务、审计、兼容、隐私和 UI 项全部有代码与自动化证据。
- 强制重下失败不会损坏旧版本；成功后播放入口只指向完整新版本。
- 工作区仅包含本规格范围内的改动。
- 不执行部署；最终报告列出改动文件、验证结果、未解决风险。
