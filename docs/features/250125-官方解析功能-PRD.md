## 1. 背景与目标

### 1.1 业务背景

当前系统支持从多个 API 站点聚合搜索视频资源，但部分资源站点返回的播放地址是加密的，需要经过官方解析器解密后才能获取真实的 m3u8 播放地址。目前系统无法处理这类加密资源，导致用户无法播放。

### 1.2 用户痛点

- **痛点 1**：部分资源站点的播放地址是加密的，无法直接播放
- **痛点 2**：用户需要手动访问解析网站解密，操作繁琐
- **痛点 3**：系统无法自动识别和处理加密资源

### 1.3 业务目标

- **主要目标**：支持官方解析资源，自动解密并播放加密视频
- **成功指标**：
  - 官方解析资源解密成功率 ≥ 90%
  - 解密后播放成功率 ≥ 95%
  - 解密耗时 ≤ 5 秒

### 1.4 项目范围

- **包含范围**：
  - config.json 配置扩展（新增 `official_parser` 字段）
  - 服务端解密 API 实现（效率优先，响应快）
  - 播放流程集成（自动识别并解密，后台处理）
  - 解密结果缓存（提升性能）
  - 错误处理和用户选择机制（解密失败时让用户选择是否切换）
- **不包含范围**：
  - 浏览器自动化解密方案（后续迭代）
  - 多解析器支持（后续扩展）

#### 功能 1：配置扩展

**优先级**：P0

**功能描述**：
在 `config.json` 的 `api_site` 配置中，为每个资源站点新增 `official_parser` 字段，用于标识该资源是否需要官方解析。

**配置格式**：

```json
{
  "api_site": {
    "example_source": {
      "api": "https://example.com/api.php/provide/vod",
      "name": "示例资源",
      "detail": "https://jx.789jiexi.com",
      "official_parser": true
    }
  }
}
```

**字段说明**：

- `official_parser`: `boolean | undefined`
  - `true`: 该资源需要官方解析
  - `false` 或 `undefined`: 该资源不需要官方解析（默认行为）

**交互流程**：

1. 系统加载 `config.json`
2. 解析 `api_site` 配置
3. 检查每个站点的 `official_parser` 字段
4. 将配置信息传递给下游处理逻辑

**边界条件**：

- `official_parser` 字段缺失：视为 `false`，使用默认播放流程
- `official_parser` 为 `null`：视为 `false`
- `official_parser` 为字符串 `"true"`：转换为 `true`
- `official_parser` 为 `true` 时：使用固定的默认解析器 URL（`https://jx.789jiexi.com`）
  - 注意：`detail` 字段仅用于爬取详情页，与官方解析无关

**验收标准**：

- [ ] 配置加载正确识别 `official_parser` 字段
- [ ] 缺失字段时使用默认值 `false`
- [ ] 类型转换正确（字符串 `"true"` → `true`）

#### 功能 2：解密 API 实现

**优先级**：P0

**功能描述**：
实现服务端解密 API，接收加密的播放地址，返回解密后的真实 m3u8 地址。

**API 接口**：

```
POST /api/decrypt
Content-Type: application/json

Request Body:
{
  "parserUrl": "https://jx.789jiexi.com",  // 解析器URL（固定默认值）
  "videoUrl": "https://www.iqiyi.com/v_xxx.html"  // 原始视频URL（从vod_play_url中提取的第三方视频网站URL）
}

Response:
{
  "success": true,
  "data": {
    "m3u8Url": "https://example.com/video.m3u8"  // 解密后的m3u8地址
  }
}
```

**解密流程**：

1. **获取 iframe URL**
   - 访问 `{parserUrl}/?url={videoUrl}`
   - 从 HTML 中提取 iframe 的 src 属性
2. **提取 ConFig 对象**
   - 访问 iframe 页面
   - 从 HTML 中提取 `ConFig.url`（加密的 URL）
   - 从 HTML 中提取 `ConFig.config.uid`（用户 ID）
3. **解密 URL**
   - 密钥生成：`key_str = '2890' + uid + 'tB959C'`
   - 密钥处理：使用 MD5 哈希生成 16 字节密钥
   - IV 生成：`iv_str = '2F131BE91247866E'`，UTF-8 编码为 16 字节
   - 解密算法：AES-CBC，PKCS7 填充
   - Base64 解码加密 URL
   - 执行 AES 解密
   - 移除 PKCS7 填充
   - 验证解密结果（应以 `http` 开头）
4. **跟踪重定向**
   - 访问解密后的 URL
   - 跟踪 HTTP 重定向（301/302/307/308）
   - 检查响应是否为 m3u8 格式（以 `#EXTM3U` 开头）
   - 如果重定向到 m3u8 API，继续跟踪直到获取最终 m3u8
   - **特殊处理**：如果解密后得到 MP4 格式的试看片段，也返回该 URL 供播放器播放

**技术实现要点**：

- 使用 Node.js 的 `crypto` 模块实现 AES 解密
- 使用 `node-fetch` 或 `undici` 进行 HTTP 请求
- 支持超时控制（30 秒）
- 支持重试机制（最多 3 次）

**边界条件**：

- iframe URL 获取失败：返回错误
- ConFig 对象提取失败：返回错误
- 解密失败（所有密钥/IV 组合都失败）：返回错误
- 重定向循环：检测并返回错误
- 网络超时：返回超时错误
- MP4 试看片段：如果解密后得到 MP4 格式的试看片段，返回该 URL（虽然不是 m3u8，但可以播放）

**验收标准**：

- [ ] 成功解密官方解析资源
- [ ] 正确处理各种错误情况
- [ ] 超时控制生效
- [ ] 重定向跟踪正确

#### 功能 3：播放流程集成

**优先级**：P0

**功能描述**：
在播放流程中自动识别官方解析资源，调用解密 API 获取真实播放地址，然后传递给播放器。

**集成点**：

1. **搜索阶段**：无需修改，搜索逻辑保持不变
2. **详情获取阶段**：无需修改，详情获取逻辑保持不变
3. **播放阶段**：检测到官方解析资源时，先解密再播放

**播放流程**：

```
用户点击播放
    ↓
获取视频详情（episodes数组）
    ↓
检查资源站点配置
    ├─ official_parser === true?
    │   ├─ 是 → 调用解密API
    │   │   ├─ 成功 → 使用解密后的URL
    │   │   └─ 失败 → 显示错误提示
    │   └─ 否 → 使用原始URL
    ↓
传递给播放器
    ↓
开始播放
```

**实现位置**：

- **前端**：`src/app/play/page.tsx` 或 `src/components/EpisodeSelector.tsx`
- **逻辑**：在设置播放 URL 前，检查资源站点配置

**代码逻辑**：

```typescript
// 伪代码
async function getPlayUrl(episodeUrl: string, source: string) {
  const config = await getConfig();
  const apiSite = config.SourceConfig.find((s) => s.key === source);

  if (apiSite?.official_parser) {
    // 使用固定的默认解析器URL（detail字段仅用于爬取详情页，不用于解析）
    const parserUrl = 'https://jx.789jiexi.com';

    // 调用解密API
    const response = await fetch('/api/decrypt', {
      method: 'POST',
      headers: { 'Content-Type': 'application/json' },
      body: JSON.stringify({
        parserUrl: parserUrl,
        videoUrl: episodeUrl,
      }),
    });

    const result = await response.json();
    if (result.success) {
      return result.data.m3u8Url;
    } else {
      throw new Error('解密失败');
    }
  }

  return episodeUrl;
}
```

**边界条件**：

- 解析器 URL：使用固定的默认值（`https://jx.789jiexi.com`），与 `detail` 字段无关
- 解密 API 调用失败：显示错误提示，允许重试
- 解密返回的 URL 无效：显示错误提示

**验收标准**：

- [ ] 自动识别官方解析资源
- [ ] 正确调用解密 API
- [ ] 解密后的 URL 正确传递给播放器
- [ ] 播放器能正常播放解密后的视频

#### 功能 4：错误处理

**优先级**：P0

**功能描述**：
提供完善的错误处理和用户友好的错误提示。

**错误类型**：

1. **配置错误**

   - `official_parser` 配置错误
   - 错误提示：`"资源配置错误，请联系管理员"`
   - 注意：解析器 URL 使用固定的默认值，不依赖 `detail` 字段

2. **网络错误**

   - 请求超时
   - 网络连接失败
   - 错误提示：`"网络连接失败，请检查网络后重试"`

3. **解密错误**

   - iframe URL 获取失败
   - ConFig 对象提取失败
   - 解密失败（所有组合都失败）
   - 错误提示：`"视频解析失败，请稍后重试或切换其他资源"`

4. **重定向错误**
   - 重定向循环
   - 无法获取最终 m3u8
   - 错误提示：`"无法获取播放地址，请稍后重试"`

**错误处理策略**：

- **自动重试**：网络错误自动重试 3 次，每次间隔 2 秒
- **用户重试**：解密错误提供"重试"按钮
- **降级处理**：解密失败时，如果还有其他资源，自动切换到下一个资源
- **日志记录**：记录所有错误日志，便于排查问题

**UI 交互**：

- 显示加载状态（"正在解析视频..."）
- 显示错误提示（红色文字，清晰的错误信息）
- 提供重试按钮
- 提供"切换其他资源"按钮

**验收标准**：

- [ ] 所有错误类型都有对应的错误提示
- [ ] 错误提示用户友好，易于理解
- [ ] 自动重试机制正常工作
- [ ] 用户重试功能正常

#### 功能 5：重定向跟踪

**优先级**：P1

**功能描述**：
跟踪解密后的 URL 重定向，直到获取最终的 m3u8 播放地址。

**重定向处理**：

1. 访问解密后的 URL
2. 检查 HTTP 状态码（301/302/303/307/308）
3. 获取 `Location` 响应头
4. 如果重定向 URL 包含 `api/m3u8` 或 `m3u8.shipinbofang.net`，继续跟踪
5. 检查响应内容是否为 m3u8 格式（以 `#EXTM3U` 开头）
6. 如果响应是 m3u8 格式，返回该 URL
7. 如果响应不是 m3u8 格式，尝试从响应中提取 m3u8 链接

**重定向限制**：

- 最多跟踪 10 次重定向
- 检测重定向循环（相同 URL 出现 2 次）
- 超时控制（每次重定向 30 秒）

**验收标准**：

- [ ] 正确跟踪重定向
- [ ] 检测重定向循环
- [ ] 超时控制生效
- [ ] 最终获取正确的 m3u8 地址

**解密模块设计**：

```typescript
// src/lib/decrypt.ts
export class OfficialParser {
  async decrypt(parserUrl: string, videoUrl: string): Promise<string> {
    // 1. 获取iframe URL
    const iframeUrl = await this.getIframeUrl(parserUrl, videoUrl);

    // 2. 提取ConFig对象
    const config = await this.extractConfig(iframeUrl);

    // 3. 解密URL
    const decryptedUrl = await this.decryptUrl(config.url, config.uid);

    // 4. 跟踪重定向
    const finalM3u8 = await this.followRedirect(decryptedUrl);

    return finalM3u8;
  }

  private async getIframeUrl(parserUrl: string, videoUrl: string): Promise<string> { ... }
  private async extractConfig(iframeUrl: string): Promise<{url: string, uid: string}> { ... }
  private async decryptUrl(encryptedUrl: string, uid: string): Promise<string> { ... }
  private async followRedirect(url: string): Promise<string> { ... }
}
```

### 5.3 接口设计

**解密 API**：

```typescript
// src/app/api/decrypt/route.ts
export async function POST(request: Request) {
  const { parserUrl, videoUrl } = await request.json();

  // 验证输入
  if (!parserUrl || !videoUrl) {
    return Response.json(
      { success: false, error: '参数缺失' },
      { status: 400 }
    );
  }

  try {
    const parser = new OfficialParser();
    const m3u8Url = await parser.decrypt(parserUrl, videoUrl);
    return Response.json({ success: true, data: { m3u8Url } });
  } catch (error) {
    return Response.json(
      { success: false, error: error.message },
      { status: 500 }
    );
  }
}
```

## 6. 风险评估

### 6.1 技术风险

- **风险**：解密算法可能与实际网站不完全匹配
- **影响**：高（导致解密失败）
- **应对**：
  - 参考 `final_direct_parser_v2.py` 的实现，尝试多种密钥/IV 组合
  - 如果 Python 版本能成功，TypeScript 版本应该也能成功
  - 提供详细的错误日志，便于调试

### 6.2 性能风险

- **风险**：解密过程耗时较长，影响用户体验
- **影响**：中（用户等待时间增加）
- **应对**：
  - 显示加载状态，让用户知道系统正在处理
  - 设置合理的超时时间（30 秒）
  - 后续优化：添加解密结果缓存

### 6.3 业务风险

- **风险**：解析网站可能变更解密算法
- **影响**：中（需要更新代码）
- **应对**：
  - 设计可扩展的解密接口，便于后续更新
  - 记录详细的错误日志，便于快速定位问题

### 10.4 实现总结

**已完成功能**：

1. ✅ **配置扩展**：在 `config.json` 中添加 `official_parser` 字段支持
2. ✅ **解密 API**：实现 `/api/decrypt` 接口，支持 AES-CBC 解密
3. ✅ **播放流程集成**：在播放页面自动识别并解密官方解析资源
4. ✅ **缓存机制**：实现内存缓存和数据库缓存，提升性能
5. ✅ **重定向跟踪**：支持跟踪解密后的重定向，获取最终 m3u8 或 MP4 试看片段
6. ✅ **多播放源提取**：从 `vod_play_url` 中提取所有播放源的所有剧集 URL
7. ✅ **错误处理**：完善的错误处理和用户友好的错误提示
8. ✅ **服务器配置 API**：修复 `/api/server-config` 返回 `SourceConfig` 信息

**关键实现细节**：

- 解密算法：参考 `final_direct_parser_v2.py`，支持多种密钥/IV 组合
- 解析器 URL：使用固定的默认值 `https://jx.789jiexi.com`，与 `detail` 字段无关
- 搜索阶段：官方解析资源提取第三方视频网站 URL（腾讯、优酷、爱奇艺等）
- 播放阶段：检测到官方解析资源时，自动调用解密 API 获取真实播放地址
- 特殊处理：支持 MP4 格式的试看片段播放
