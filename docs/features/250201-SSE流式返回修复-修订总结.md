## 1. 问题描述

### 1.1 用户反馈的问题

1. **Worker 搜索源问题**：

   - 配置了很多源，但实际搜索结果好像并没有全部都搜
   - 例如 `gay` 资源单独调用接口有数据返回，但调用封装的接口就没有数据了

2. **SSE 流式返回问题**：
   - 虽然使用了 SSE（Server-Sent Events），但实际感觉还是等待所有源完成后才统一返回结果
   - 不应该是每个源完成后立即返回，而是等待所有源完成
   - 前端日志显示只收到一次结果消息，而不是多次流式消息

### 1.2 问题分析

**Worker 搜索源问题**：

- 某些源配置缺失（如 `xjcj`）
- 超时时间太短（3 秒），慢速源无法完成搜索
- 错误被静默忽略，无法追踪问题
- 并发安全问题：多个 Promise 同时访问和修改共享的 `seenResults` Set

**SSE 流式返回问题**：

- `searchOfficialResources` 和 `searchUnofficialResources` 函数使用 `await response.text()` 等待整个响应完成
- 本地 API 等待这两个函数完成后才推送结果，导致不是真正的流式返回
- 消息格式问题：`source` 和 `source_name` 在 `debug` 对象中，不在顶层

## 4. 技术细节

### 4.1 Worker 流式返回实现

Worker 使用 `TransformStream` 和 `writer.write()` 实现流式返回：

```typescript
const { readable, writable } = new TransformStream();
const writer = writable.getWriter();
const encoder = new TextEncoder();

// 每个源完成后立即推送
await writer.write(encoder.encode(`data: ${message}\n\n`));
```

### 4.2 本地 API 流式处理实现

本地 API 使用 `response.body.getReader()` 流式处理 SSE 响应：

```typescript
const reader = response.body?.getReader();
const decoder = new TextDecoder();
let buffer = '';

while (true) {
  const { done, value } = await reader.read();
  if (done) break;

  buffer += decoder.decode(value, { stream: true });
  const lines = buffer.split('\n');
  buffer = lines.pop() || '';

  // 逐行处理 SSE 消息
  for (const line of lines) {
    if (trimmedLine.startsWith('data:')) {
      // 立即推送结果
    }
  }
}
```

### 4.3 前端 SSE 处理

前端使用 `EventSource` 处理 SSE 流：

```typescript

eventSource.onmessage = (event) => {
```

## 7. 注意事项

1. **Worker 超时时间**：

   - 当前设置为 15 秒，如果某些源响应很慢，可能需要进一步增加
   - 但超时时间过长会影响整体搜索体验

2. **SSE 流式处理**：

   - 如果上游 API 不是 SSE 格式，会回退到原来的方法（等待所有数据完成）
   - 确保上游 API 支持 SSE 格式才能享受流式返回的优势

3. **日志输出**：
   - 详细日志有助于调试，但会增加日志量
   - 生产环境可以考虑减少日志输出
