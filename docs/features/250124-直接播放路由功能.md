## 🎯 功能概述

实现了直接播放路由功能，用户可以通过 `/player?url=<视频地址>` 的方式直接播放视频，无需经过搜索、详情页等复杂流程。

---

## ✅ 实现内容

### 1. 路由创建

- **文件**：`src/app/player/page.tsx`
- **路由路径**：`/player`
- **功能**：独立的播放页面，支持通过 URL 参数传递视频地址

### 2. URL 参数解析

- **参数名**：`url`
- **功能**：
  - 自动解码 URL 编码的视频地址
  - 支持包含多个查询参数的 URL（如 `&act=.m3u8`）
  - 从完整页面 URL 中恢复被截断的参数
  - URL 格式验证

### 3. 播放器集成

- **播放器库**：ArtPlayer + HLS.js
- **配置**：复用现有播放页面的播放器配置
- **功能**：
  - 支持 m3u8 格式播放
  - 自动播放
  - 播放器控制（全屏、倍速、音量等）
  - 去广告功能支持

### 4. 状态管理

- **加载状态**：显示加载动画和提示
- **错误处理**：友好的错误提示和重试机制
- **容器管理**：确保播放器容器 DOM 始终渲染

### 5. 响应式布局

- **移动端适配**：自适应移动端屏幕
- **桌面端适配**：居中显示，最大宽度限制
- **布局组件**：集成 PageLayout，支持返回按钮

## 🔧 技术实现

### 核心代码结构

```
src/app/player/
└── page.tsx          # 播放页面组件
    ├── URL参数解析    # 从searchParams获取并解码URL
    ├── 播放器初始化   # ArtPlayer + HLS.js配置
    ├── 状态管理       # loading, error, containerReady
    └── UI渲染         # 加载/错误/播放器界面
```

### 关键技术点

1. **URL 参数处理**

   - 使用 `useSearchParams` 获取 URL 参数
   - 处理 URL 编码和解码
   - 支持包含多个查询参数的 URL

2. **播放器容器管理**

   - 使用 ref 回调确保容器挂载
   - 容器 DOM 始终渲染，使用 `visibility` 控制显示
   - 状态同步机制确保初始化时机正确

3. **错误处理**
   - HLS 错误自动恢复（网络错误、媒体错误）
   - 用户友好的错误提示
   - 重试机制

## 🐛 问题修复

### 问题 1：播放器容器未渲染

**现象**：`artRef.current` 始终为 `null`，播放器无法初始化

**原因**：加载/错误状态下组件提前返回，容器 DOM 未渲染

**解决方案**：

- 确保容器 DOM 始终渲染
- 使用 `visibility: hidden` 和 `position: absolute` 控制显示
- 优化 ref 回调逻辑

**相关文档**：[播放器容器初始化失败修复](fixes/250124-播放器容器初始化失败-FIX.md)

## 📝 使用说明

### 基本用法

```
/player?url=<视频地址>
```

### URL 编码

如果视频 URL 包含多个查询参数，需要完整编码：

```javascript
// 原始URL
https://example.com/video.m3u8?key=xxx&act=.m3u8

// 编码后（使用 encodeURIComponent）
https%3A%2F%2Fexample.com%2Fvideo.m3u8%3Fkey%3Dxxx%26act%3D.m3u8

// 完整访问地址
/player?url=https%3A%2F%2Fexample.com%2Fvideo.m3u8%3Fkey%3Dxxx%26act%3D.m3u8
```

### 示例

```
/player?url=https://example.com/video.m3u8
/player?url=https%3A%2F%2Fexample.com%2Fvideo.m3u8
```
