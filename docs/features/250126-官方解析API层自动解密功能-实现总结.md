## 1. 功能概述

官方解析 API 层自动解密功能已完整实现，支持在 API 层自动解密官方解析资源，返回真实的 m3u8 或 MP4 播放地址，使 OrionTV 等第三方客户端可以直接使用解密后的 URL。

### 1.1 核心功能

- ✅ **代码重构**：提取解密核心逻辑到独立模块
- ✅ **API 层自动解密**：在 `searchFromApi` 和 `getDetailFromApi` 中自动解密
- ✅ **Edge Runtime 兼容**：通过 HTTP API 调用解决 Edge Runtime 不支持 Node.js crypto 的问题
- ✅ **错误处理**：解密失败时清空 episodes，不返回无法播放的原始 URL
- ✅ **数据可用性**：确保只有解密成功的 URL 才会返回给客户端

### 2.1 第一阶段：代码重构

#### 2.1.1 提取核心逻辑

**文件**：`src/lib/decrypt.ts`

**实现内容**：

- 从 `/api/decrypt/route.ts` 提取所有解密相关函数
- 实现 `decryptEpisodeUrl`：单个 URL 解密（支持 Edge Runtime）
- 实现 `decryptEpisodeUrls`：批量并发解密
- 实现缓存机制（内存缓存 + 数据库缓存）
- 实现超时控制（10 秒）

**关键函数**：

```typescript
// 检测 Edge Runtime 环境
function isEdgeRuntime(): boolean;

// 获取基础 URL（修复 0.0.0.0 -> localhost）
function getBaseUrl(requestUrl?: string): string;

// 解密单个 URL（支持 Edge Runtime）
export async function decryptEpisodeUrl(
  parserUrl: string,
  videoUrl: string,
  useHttpApi = false,

// 批量解密 URL
export async function decryptEpisodeUrls(
```

#### 2.1.2 Edge Runtime 兼容性

**问题**：Edge Runtime 不支持 Node.js `crypto` 模块

**解决方案**：

- 检测运行环境（`isEdgeRuntime()`）
- Edge Runtime 中通过 HTTP API 调用 `/api/decrypt`
- Node.js Runtime 中直接调用内部函数
- `/api/decrypt` 路由使用 Node.js Runtime

**关键修复**：

- 修复 base URL 获取：`0.0.0.0` → `localhost`
- 从请求 URL 中提取 origin
- 支持多种环境变量（`NEXT_PUBLIC_BASE_URL`、`VERCEL_URL`）

#### 2.1.3 API 路由重构

**文件**：`src/app/api/decrypt/route.ts`

**修改内容**：

- 设置为 Node.js Runtime（`export const runtime = 'nodejs'`）
- 调用 `decryptEpisodeUrl` 内部函数
- 保持 API 接口不变，确保向后兼容

### 2.3 关键修复

#### 2.3.1 修复 base URL 获取

**问题**：Edge Runtime 中获取的 base URL 是 `http://0.0.0.0:51000`，无法访问

**修复**：在 `getBaseUrl()` 函数中将 `0.0.0.0` 替换为 `localhost`

```typescript
if (origin.includes('0.0.0.0')) {
  origin = origin.replace('0.0.0.0', 'localhost');
}
```

#### 2.3.2 修复 401 错误

**问题**：`/api/decrypt` 路由被 middleware 拦截，返回 401

**修复**：将 `/api/decrypt` 添加到 middleware 跳过认证列表

```typescript
matcher: [
  '/((?!_next/static|_next/image|favicon.ico|login|warning|api/login|api/register|api/logout|api/cron|api/server-config|api/decrypt).*)',
],
```

#### 2.3.3 修复解密失败处理

**问题**：解密失败时返回原始 URL，但原始 URL 无法播放

**修复**：

- `decryptEpisodeUrl`：解密失败时抛出错误（不返回原始 URL）
- `decryptEpisodeUrls`：失败时返回空字符串
- `searchFromApi` 和 `getDetailFromApi`：过滤掉空字符串，解密失败时清空所有 episodes

#### 2.3.4 修复配置传递

**问题**：`getAvailableApiSites()` 返回的 `ApiSite` 缺少 `official_parser` 字段

**修复**：在 `src/lib/config.ts` 中更新 `getAvailableApiSites()`，返回时包含 `official_parser` 字段

## 3. 技术架构

### 3.1 运行环境适配

```
Edge Runtime (searchFromApi, getDetailFromApi)
  ↓
检测到 official_parser === true
  ↓
通过 HTTP API 调用 /api/decrypt
  ↓
Node.js Runtime (/api/decrypt)
  ↓
调用内部解密函数（使用 Node.js crypto）
  ↓
返回解密后的 m3u8 地址
```

### 3.2 解密流程

```
1. 获取 iframe URL
   ↓
2. 访问 iframe 页面，提取 ConFig 对象
   ↓
3. AES-CBC 解密 ConFig.url
   ↓
4. 跟踪重定向，获取最终 m3u8 地址
   ↓
5. 返回解密结果（失败时抛出错误）
```

### 3.3 错误处理策略

- **单个 URL 解密失败**：返回空字符串，不影响其他 URL
- **批量解密失败**：过滤掉失败的 URL，返回成功解密的 URL
- **整个解密过程失败**：清空所有 episodes，不返回无法播放的 URL

## 4. 关键决策

### 4.1 解密失败不返回原始 URL

**决策**：解密失败时返回空数组，不返回原始 URL

**原因**：

- 原始 URL（第三方视频网站链接）无法直接播放
- 返回无法播放的 URL 会误导用户
- 清空 episodes 让客户端知道该资源不可用

### 4.2 Edge Runtime 通过 HTTP API 调用

**决策**：Edge Runtime 中通过 HTTP API 调用解密功能

**原因**：

- Edge Runtime 不支持 Node.js `crypto` 模块
- 解密逻辑复杂，无法使用 Web Crypto API 完全替代
- HTTP API 调用是最简单的解决方案

### 4.3 只有 official_parser: true 的源才解密

**决策**：严格检查 `official_parser` 配置

**原因**：

- 避免对普通资源进行不必要的解密操作
- 提高性能，减少不必要的 API 调用
- 确保只有需要解密的资源才会被处理

## 6. 已知问题与限制

### 6.1 性能影响

- **解密耗时**：单个 URL 解密需要 3-10 秒
- **批量解密**：10 个 URL 并发解密需要 10-15 秒
- **缓存优化**：已实现缓存机制，缓存命中时 < 1 秒

### 6.2 解密成功率

- **取决于解析网站稳定性**：部分资源可能解密失败
- **试看片段限制**：部分资源只能获取 5 分钟试看片段
- **错误处理**：解密失败时清空 episodes，不返回无法播放的 URL

### 6.3 环境依赖

- **Edge Runtime**：需要通过 HTTP API 调用解密
- **Node.js Runtime**：直接调用内部函数
- **网络要求**：需要能够访问解析器网站
