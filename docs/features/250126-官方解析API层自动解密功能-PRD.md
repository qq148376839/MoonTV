## 1. 背景与目标

### 1.1 业务背景

当前 MoonTV 的官方解析功能仅在网页端播放时进行解密，当 MoonTV 作为 OrionTV 后端时，API 返回的是第三方视频网站 URL（如 `https://v.qq.com/x/cover/xxx.html`），OrionTV 客户端无法直接播放这些 URL，导致官方解析资源无法在 Android TV 上使用。

### 1.2 用户痛点?

- **OrionTV 用户**：无法播放官方解析资源，只能使用普通资源
- **API 调用者**：需要自行实现解密逻辑，增加集成复杂度
- **开发者**：需要在客户端和服务器端重复实现解密逻辑

### 1.3 业务目标

- **主要目标**：在 API 层自动解密官方解析资源，返回真实的 m3u8 或 MP4 地址
- **成功指标**：
  - OrionTV 可以正常播放官方解析资源
  - API 响应时间增加 ≤ 5 秒（有缓存时 ≤ 1 秒）
  - 解密成功率 ≥ 90%
  - 不影响现有网页端功能

### 1.4 项目范围

- **包含范围**：
  - `/api/search/one` - 单源搜索 API
  - `/api/detail` - 视频详情 API
  - `/api/search` - 多源搜索 API（可选，性能考虑）
- **不包含范围**：
  - `/api/search/resources` - 资源列表 API（无需解密）
  - 网页端播放逻辑（保持现有实现）
  - 其他第三方客户端适配

## 3. 功能需求

### 3.1 功能概览

| 功能           | 优先级 | 说明                                  |
| -------------- | ------ | ------------------------------------- |
| API 层自动解密 | P0     | 在 API 返回前自动解密官方解析资源     |
| 批量解密优化   | P1     | 并发解密多个剧集 URL，提升性能        |
| 错误降级处理   | P0     | 解密失败时返回原始 URL，保证可用性    |
| 性能优化       | P1     | 利用现有缓存机制，减少重复解密        |
| 超时控制       | P0     | 设置合理的超时时间，避免 API 响应过慢 |

### 3.2 功能详细说明

#### 功能 1：API 层自动解密

**优先级**：P0

**功能描述**：
在 `searchFromApi` 和 `getDetailFromApi` 函数中，检测到 `official_parser=true` 时，自动解密所有剧集 URL，返回真实的 m3u8 或 MP4 地址。

**交互流程**：

1. API 从资源站获取视频数据
2. 检查源的 `official_parser` 配置
3. 如果为 `true`，提取第三方视频网站 URL
4. 调用内部解密函数解密所有 URL
5. 返回解密后的 URL 列表

**输入输出**：

- **输入**：第三方视频网站 URL（如 `https://v.qq.com/x/cover/xxx.html`）
- **输出**：真实的 m3u8 或 MP4 地址（如 `https://example.com/video.m3u8`）

**边界条件**：

- 解密失败：返回原始 URL，不中断流程
- 超时：单个 URL 解密超时（10 秒），返回原始 URL
- 缓存命中：直接返回缓存的解密结果
- 空 URL 列表：跳过解密，直接返回

**验收标准**：

- [ ] 官方解析资源的 URL 在 API 返回前已解密
- [ ] 解密失败时返回原始 URL，不抛出错误
- [ ] 解密超时时返回原始 URL，不阻塞 API 响应
- [ ] 缓存命中时响应时间 < 1 秒

#### 功能 2：批量解密优化

**优先级**：P1

**功能描述**：
使用 `Promise.allSettled` 并发解密多个剧集 URL，提升性能。

**交互流程**：

1. 收集所有需要解密的 URL
2. 使用 `Promise.allSettled` 并发解密
3. 等待所有解密完成（无论成功或失败）
4. 合并结果，失败的返回原始 URL

**性能要求**：

- 单个 URL 解密耗时：3-10 秒
- 10 个 URL 并发解密耗时：≤ 15 秒
- 缓存命中时：< 1 秒

**验收标准**：

- [ ] 多个 URL 并发解密，不串行执行
- [ ] 解密失败不影响其他 URL 的解密
- [ ] 性能符合要求

#### 功能 3：错误降级处理

**优先级**：P0

**功能描述**：
解密失败时，返回原始 URL，确保 API 始终返回可用数据。

**错误类型**：

- 网络错误：解析器网站不可用
- 解密失败：无法解密 URL
- 超时错误：解密过程超时
- 格式错误：解密后的 URL 格式不正确

**处理策略**：

- 所有错误都静默处理，不抛出异常
- 记录错误日志（开发环境）
- 返回原始 URL，让客户端决定如何处理

**验收标准**：

- [ ] 任何错误都不会导致 API 返回 500
- [ ] 错误时返回原始 URL
- [ ] 错误日志正确记录

## 4. 技术方案

### 4.1 架构设计

```
API 请求
  ↓
获取视频数据（searchFromApi / getDetailFromApi）
  ↓
检查 official_parser 配置
  ↓
是 → 提取第三方视频网站 URL
  ↓
调用内部解密函数（decryptEpisodeUrl）
  ↓
批量并发解密（Promise.allSettled）
  ↓
合并结果（成功：解密URL，失败：原始URL）
  ↓
返回 API 响应
```

### 4.2 核心函数设计

#### 4.2.1 内部解密函数

**位置**：`src/lib/decrypt.ts`

**函数签名**：

```typescript
/**
 * 解密单个剧集 URL（内部调用，不通过 HTTP）
 * @param parserUrl 解析器 URL（默认：https://jx.789jiexi.com）
 * @param videoUrl 第三方视频网站 URL
 * @returns Promise<string> 解密后的 m3u8 或 MP4 地址，失败返回原始 URL
 */
export async function decryptEpisodeUrl(
  parserUrl: string,
  videoUrl: string
): Promise<string>;
```

**实现要点**：

- 复用现有的 `decryptVideo` 逻辑（从 `/api/decrypt/route.ts` 提取）
- 使用相同的缓存机制
- 设置 10 秒超时
- 错误时返回原始 URL

#### 4.2.2 批量解密函数

**位置**：`src/lib/decrypt.ts`

**函数签名**：

```typescript
/**
 * 批量解密剧集 URL
 * @param parserUrl 解析器 URL
 * @param videoUrls 第三方视频网站 URL 数组
 * @returns Promise<string[]> 解密后的 URL 数组，失败项返回原始 URL
 */
export async function decryptEpisodeUrls(
  parserUrl: string,
  videoUrls: string[]
): Promise<string[]>;
```

**实现要点**：

- 使用 `Promise.allSettled` 并发解密
- 每个 URL 独立处理，失败不影响其他
- 返回结果数组，顺序与输入一致

### 4.4 性能优化

#### 4.4.1 缓存机制

- **复用现有缓存**：使用 `/api/decrypt` 的缓存机制
- **缓存键格式**：`decrypt:{parserUrl}:{videoUrl}`
- **缓存 TTL**：1 小时

#### 4.4.2 并发控制

- **并发数量**：无限制（使用 `Promise.allSettled`）
- **超时控制**：每个 URL 10 秒超时
- **失败处理**：单个失败不影响其他

#### 4.4.3 超时策略

- **单个 URL 解密超时**：10 秒
- **批量解密总超时**：无限制（等待所有完成）
- **API 响应超时**：由服务器配置决定（通常 30-60 秒）

## 5. 约束条件与风险控制

### 5.1 向后兼容性

**约束**：

- 不修改现有 API 接口签名
- 不修改现有数据结构
- 网页端播放逻辑保持不变

**验证**：

- [ ] 网页端播放功能正常
- [ ] 现有 API 调用不受影响
- [ ] 非官方解析资源行为不变

### 5.2 性能约束

**约束**：

- API 响应时间增加 ≤ 5 秒（无缓存）
- API 响应时间增加 ≤ 1 秒（有缓存）
- 不影响非官方解析资源的响应时间

**风险控制**：

- 使用缓存减少重复解密
- 设置合理的超时时间
- 解密失败时快速降级

### 5.3 错误处理约束

**约束**：

- 任何错误都不能导致 API 返回 500
- 解密失败时必须返回原始 URL
- 错误日志必须记录（开发环境）

**风险控制**：

- 所有解密操作使用 try-catch 包裹
- 使用 `Promise.allSettled` 确保单个失败不影响整体
- 错误时返回原始 URL，保证可用性

### 5.4 资源消耗约束

**约束**：

- 解密过程需要多次 HTTP 请求，消耗服务器资源
- 并发解密可能增加服务器负载

**风险控制**：

- 使用缓存减少重复请求
- 设置超时避免长时间占用资源
- 监控服务器负载，必要时限制并发数

### 5.5 数据一致性约束

**约束**：

- 解密后的 URL 必须有效
- URL 顺序必须与输入一致
- 不能丢失任何 URL

**风险控制**：

- 验证解密后的 URL 格式
- 使用 `Promise.allSettled` 保持顺序
- 失败时返回原始 URL，不丢失数据
