## 1. 背景与目标

### 1.1 业务背景

用户希望能够通过直接传递视频 URL 的方式快速播放视频，无需经过搜索、详情页等复杂流程。这对于已知视频地址的场景（如外部链接、API 返回的播放地址等）非常有用。

### 1.2 用户痛点

- 当前播放流程需要先搜索、选择资源站、查看详情，步骤较多
- 当用户已经知道视频地址时，无法直接播放
- 外部系统集成时需要更简单的播放入口

### 1.3 业务目标

- **主要目标**：提供直接播放功能，简化播放流程
- **成功指标**：
  - 播放成功率 ≥ 95%
  - 页面加载时间 ≤ 2 秒
  - 支持所有播放器已支持的视频格式（m3u8 等）

### 1.4 项目范围

- **包含范围**：
  - 新建独立路由 `/player`
  - 通过 `url` 参数传递视频地址
  - 播放器加载和播放功能
  - 加载状态提示
  - 播放器控制（全屏、倍速等）
  - 错误提示和重试机制
  - 响应式布局适配
- **不包含范围**：
  - 视频信息展示（标题、封面等）
  - 收藏功能
  - 播放记录功能
  - URL 格式验证和白名单限制

## 2. 用户与场景

### 2.1 目标用户

- **主要用户**：需要快速播放已知视频地址的用户
- **用户特征**：已获得视频播放地址，希望直接播放

### 2.2 使用场景

**场景 1：外部链接播放**

- **用户**：普通用户
- **时间**：任意时间
- **地点**：任意地点
- **行为**：从其他系统或 API 获取到视频地址，希望直接播放
- **目标**：快速打开并播放视频

**场景 2：API 集成播放**

- **用户**：开发者或系统集成者
- **时间**：系统调用时
- **地点**：通过 API 调用
- **行为**：通过 API 获取视频地址后，需要嵌入播放页面
- **目标**：提供简单的播放入口

### 2.3 用户故事

- As a 用户, I want 通过 URL 参数直接播放视频, So that 我可以快速播放已知地址的视频
- As a 开发者, I want 简单的播放路由, So that 我可以轻松集成到其他系统中

## 3. 功能需求

### 3.1 功能概览

| 功能         | 优先级 | 说明                      |
| ------------ | ------ | ------------------------- |
| URL 参数解析 | P0     | 从 URL 参数中获取视频地址 |
| 播放器初始化 | P0     | 初始化 ArtPlayer 播放器   |
| 视频加载     | P0     | 加载并播放视频            |
| 加载状态提示 | P1     | 显示加载中的状态          |
| 错误处理     | P0     | 处理播放错误并提示        |
| 重试机制     | P1     | 播放失败时提供重试功能    |
| 播放器控制   | P1     | 支持全屏、倍速等控制      |
| 响应式布局   | P1     | 适配移动端和桌面端        |

### 3.2 功能详细说明

#### 功能 1：URL 参数解析

**优先级**：P0

**功能描述**：
从路由的 URL 参数中解析出视频播放地址。

**交互流程**：

1. 用户访问 `/player?url=https://example.com/video.m3u8`
2. 系统解析 URL 参数，获取 `url` 值
3. 验证 URL 参数是否存在
4. 将 URL 传递给播放器组件

**输入输出**：

- **输入**：URL 参数 `url`（视频地址）
- **输出**：解析后的视频地址字符串

**边界条件**：

- URL 参数缺失：显示错误提示"请提供视频地址"
- URL 格式错误：由播放器处理，显示播放错误

**验收标准**：

- [ ] 可以正确解析 URL 参数
- [ ] URL 参数缺失时显示错误提示
- [ ] 支持 URL 编码的视频地址

#### 功能 2：播放器初始化

**优先级**：P0

**功能描述**：
初始化 ArtPlayer 播放器，配置 HLS.js 支持 m3u8 格式。

**交互流程**：

1. 获取视频 URL 后，初始化播放器容器
2. 创建 ArtPlayer 实例
3. 配置 HLS.js 支持 m3u8 格式
4. 设置播放器基本配置（全屏、倍速等）

**输入输出**：

- **输入**：视频 URL
- **输出**：初始化的播放器实例

**边界条件**：

- HLS.js 未加载：显示错误提示
- 播放器初始化失败：显示错误提示

**验收标准**：

- [ ] 播放器可以正常初始化
- [ ] 支持 m3u8 格式播放
- [ ] 播放器配置正确（全屏、倍速等）

#### 功能 3：视频加载和播放

**优先级**：P0

**功能描述**：
加载视频并自动开始播放。

**交互流程**：

1. 播放器初始化完成后，开始加载视频
2. 显示加载状态
3. 视频加载完成后自动播放
4. 隐藏加载状态

**输入输出**：

- **输入**：视频 URL
- **输出**：播放中的视频

**边界条件**：

- 视频加载超时：显示错误提示，提供重试按钮
- 网络错误：显示错误提示，提供重试按钮
- 视频格式不支持：显示错误提示

**验收标准**：

- [ ] 视频可以正常加载
- [ ] 视频加载完成后自动播放
- [ ] 加载过程中显示加载状态

#### 功能 4：加载状态提示

**优先级**：P1

**功能描述**：
在视频加载过程中显示加载状态提示。

**交互流程**：

1. 开始加载视频时显示加载提示
2. 加载完成后隐藏加载提示

**输入输出**：

- **输入**：加载状态（loading/ready/error）
- **输出**：加载状态 UI 显示

**边界条件**：

- 加载时间过长：继续显示加载提示
- 加载失败：切换到错误状态

**验收标准**：

- [ ] 加载时显示加载提示
- [ ] 加载完成后隐藏加载提示
- [ ] 加载提示样式美观

#### 功能 5：错误处理和提示

**优先级**：P0

**功能描述**：
处理播放过程中的错误，并显示友好的错误提示。

**交互流程**：

1. 检测到播放错误
2. 显示错误提示信息
3. 提供重试按钮

**输入输出**：

- **输入**：错误信息
- **输出**：错误提示 UI

**边界条件**：

- 网络错误：显示"网络错误，请检查网络连接"
- 视频格式错误：显示"视频格式不支持或地址无效"
- 服务器错误：显示"服务器错误，请稍后重试"

**验收标准**：

- [ ] 错误时显示错误提示
- [ ] 错误提示信息清晰明确
- [ ] 提供重试按钮

#### 功能 6：重试机制

**优先级**：P1

**功能描述**：
播放失败时提供重试功能。

**交互流程**：

1. 播放失败后显示错误提示
2. 用户点击重试按钮
3. 重新加载视频
4. 如果仍然失败，继续显示错误提示

**输入输出**：

- **输入**：重试操作
- **输出**：重新加载的视频

**边界条件**：

- 重试次数：不限制，用户可以多次重试
- 重试时显示加载状态

**验收标准**：

- [ ] 可以点击重试按钮
- [ ] 重试时重新加载视频
- [ ] 重试时显示加载状态

#### 功能 7：播放器控制

**优先级**：P1

**功能描述**：
提供播放器基本控制功能（全屏、倍速、音量等）。

**交互流程**：

1. 播放器提供控制栏
2. 用户可以调整音量、倍速
3. 用户可以全屏播放
4. 用户可以暂停/播放

**输入输出**：

- **输入**：用户操作
- **输出**：播放器状态变化

**边界条件**：

- 全屏功能受浏览器限制
- 倍速范围：0.5x - 2.0x

**验收标准**：

- [ ] 可以调整音量
- [ ] 可以调整倍速
- [ ] 可以全屏播放
- [ ] 可以暂停/播放

#### 功能 8：响应式布局

**优先级**：P1

**功能描述**：
适配移动端和桌面端的不同屏幕尺寸。

**交互流程**：

1. 检测屏幕尺寸
2. 根据屏幕尺寸调整播放器大小和布局
3. 移动端优化触摸操作

**输入输出**：

- **输入**：屏幕尺寸
- **输出**：适配后的布局

**边界条件**：

- 移动端：播放器宽度 100%，高度自适应
- 桌面端：播放器居中显示，最大宽度限制

**验收标准**：

- [ ] 移动端显示正常
- [ ] 桌面端显示正常
- [ ] 播放器大小自适应屏幕

## 4. 非功能需求

### 4.1 性能要求

- **页面加载时间**：≤ 2 秒
- **播放器初始化时间**：≤ 1 秒
- **视频加载时间**：取决于网络速度，但需显示加载状态

### 4.2 安全要求

- 受现有 middleware 保护，需要登录验证
- 不进行 URL 格式验证和白名单限制
- 支持播放器已支持的所有视频格式

### 4.3 兼容性要求

- 支持主流浏览器（Chrome、Firefox、Safari、Edge）
- 支持移动端浏览器（iOS Safari、Android Chrome）
- 支持 HLS 格式（m3u8）播放

## 5. 技术方案

### 5.1 技术选型

- **路由**：Next.js App Router，新建 `/player` 路由
- **播放器**：复用现有 ArtPlayer + HLS.js 配置
- **组件**：新建独立的播放页面组件

### 5.2 架构设计

```
src/app/player/
├── page.tsx          # 播放页面组件
└── (复用现有组件和工具)
    ├── ArtPlayer     # 播放器库
    ├── HLS.js        # HLS支持
    └── PageLayout    # 页面布局
```

### 5.3 接口设计

**路由格式**：

```
/player?url=<视频地址>
```

**示例**：

```
/player?url=https://example.com/video.m3u8
/player?url=https%3A%2F%2Fexample.com%2Fvideo.m3u8  (URL编码)
```

## 6. 风险评估

### 6.1 技术风险

- **风险**：视频地址无效或无法访问
- **影响**：中（影响用户体验）
- **应对**：提供错误提示和重试机制

### 6.2 业务风险

- **风险**：用户可能传递恶意 URL
- **影响**：低（受现有 middleware 保护）
- **应对**：依赖现有安全机制，不额外验证
