## 🔍 问题分析

### 当前问题

**现象**：虽然配置了 `LOCAL_STORAGE_MAX_CONCURRENT` 环境变量，但在下载包含大量 TS 片段的 M3U8 视频时，TS 片段仍然是**串行下载**（一个接一个），导致下载速度极慢。

**影响范围**：

- 单个剧集包含 1326 个 TS 片段时，串行下载耗时过长
- 用户体验差，等待时间过长
- 资源利用率低，网络带宽和 CPU 未充分利用

### 根本原因

通过代码分析发现：

1. **并发控制层级错误**：

   - `LOCAL_STORAGE_MAX_CONCURRENT` 只控制了**任务级别**（剧集级别）的并发
   - 即：同时可以下载多少个**剧集**
   - 但**不控制**单个剧集内 TS 片段的并发

2. **TS 片段下载实现**：

   ```typescript
   // src/lib/download-service.ts:445-463
   // 当前实现：串行 for 循环
   for (let i = 0; i < tsUrls.length; i++) {
     const tsUrl = tsUrls[i];
     // ...
     const segmentSize = await this.downloadFile(tsUrl, segmentFilePath); // 等待完成
     // ...
   }
   ```

3. **并发配置使用位置**：
   - `maxConcurrent` 只在 `processQueue()` 中使用（控制任务并发）
   - 未在 `downloadM3U8()` 的 TS 片段下载中使用

## 💡 优化方案

### 方案概述

实现**两级并发控制**：

1. **任务级并发**：控制同时下载的剧集数量（已有）
2. **片段级并发**：控制单个剧集内 TS 片段的并发下载数（新增）

### 技术方案

#### 方案 1：基于 Promise 的并发控制

**实现思路**：

- 使用 `Promise.all()` 或 `Promise.allSettled()` 实现并发
- 使用信号量（Semaphore）或队列控制并发数
- 保持进度回调的实时性

**优点**：

- 实现简单，代码改动小
- 性能提升明显
- 易于控制并发数
- 无需新增依赖

**缺点**：

- 需要手动管理并发队列
- 代码复杂度较高
- 需要处理边界情况
- 维护成本较高

#### 方案 2：使用 p-limit 库（推荐）⭐

**实现思路**：

- 使用 `p-limit` 库控制并发
- 自动管理并发队列
- 代码更简洁

**优点**：

- ✅ 代码简洁，维护性好（核心优势）
- ✅ 自动处理并发控制，无需手动管理队列
- ✅ 社区成熟，稳定可靠（GitHub 5k+ stars，广泛使用）
- ✅ 轻量级库（仅几 KB，对项目影响小）
- ✅ 经过充分测试，边界情况处理完善
- ✅ 支持动态调整并发数
- ✅ 更好的错误处理和资源管理

**缺点**：

- 需要新增依赖（但影响极小，p-limit 非常轻量）

#### 方案 3：自定义并发队列

**实现思路**：

- 实现一个简单的并发队列类
- 手动管理并发任务
- 完全控制并发逻辑

**优点**：

- 无外部依赖
- 完全可控
- 可定制化

**缺点**：

- 实现复杂度较高
- 需要更多测试

### 推荐方案：方案 2（使用 p-limit 库）⭐

**理由**：

1. **代码质量优先**：p-limit 提供了更简洁、更易维护的代码，减少自定义实现的复杂度
2. **稳定性保障**：p-limit 是经过大量项目验证的成熟库，边界情况处理更完善
3. **维护成本低**：无需维护自定义并发控制逻辑，减少潜在 bug
4. **依赖影响小**：p-limit 是一个非常轻量级的库（仅几 KB），对项目影响极小
5. **功能更强大**：支持动态调整并发数、更好的错误处理等高级特性
6. **团队协作**：使用标准库更容易被团队成员理解和维护

**权衡分析**：

- 虽然需要新增一个依赖，但 p-limit 的轻量级特性和带来的代码质量提升，完全值得这个权衡
- 相比自定义实现，使用成熟库可以降低长期维护成本和技术债务

**核心实现**：

```typescript
import pLimit from 'p-limit';

// 在 DownloadService 类中
private tsConcurrent: number;
private tsLimit: ReturnType<typeof pLimit>;

constructor() {
  this.storageManager = getStorageManager();
  this.maxConcurrent =
    parseInt(process.env.LOCAL_STORAGE_MAX_CONCURRENT || '3', 10) || 3;

  // 新增：TS 片段并发数配置
  this.tsConcurrent =
    parseInt(process.env.LOCAL_STORAGE_TS_CONCURRENT || '5', 10) || 5;

  // 创建 p-limit 实例
  this.tsLimit = pLimit(this.tsConcurrent);
}

// 在 downloadM3U8() 方法中
private async downloadM3U8(
  m3u8Url: string,
  localPath: string,
  episodeIndex: number,
  progressCallback?: (progress: number) => void
): Promise<{ localFilePath: string; fileSize: number }> {
  // ... 前面的代码保持不变 ...

  // 下载所有 TS 片段（使用 p-limit 控制并发）
  let totalSize = 0;
  let completed = 0;

  const downloadPromises = tsUrls.map((tsUrl, i) =>
    this.tsLimit(async () => {
      const segmentFileName = `segment_${i.toString().padStart(3, '0')}.ts`;
      const segmentFilePath = path.join(episodeDir, segmentFileName);

      try {
        const segmentSize = await this.downloadFile(tsUrl, segmentFilePath);
        totalSize += segmentSize;
        completed++;

        // 更新进度
        if (progressCallback) {
          const progress = (completed / tsUrls.length) * 100;
          progressCallback(progress);
        }
      } catch (error) {
        console.error(`[DownloadService] 下载 TS 片段失败: ${tsUrl}`, error);
        // p-limit 会自动处理错误，不会影响其他任务
      }
    })
  );

  // 等待所有下载完成（无论成功或失败）
  await Promise.allSettled(downloadPromises);

  // ... 后面的代码保持不变 ...
}
```

**p-limit 的优势**：

- 自动管理并发队列，无需手动实现信号量
- 自动处理错误，单个任务失败不影响其他任务
- 代码简洁，易于理解和维护
- 支持动态调整并发数（通过 `limit.concurrency` 属性）

## ⚠️ 风险和注意事项

### 技术风险

1. **内存占用增加**：

   - 风险：并发下载可能占用更多内存
   - 缓解：限制并发数，监控内存使用

2. **网络连接数限制**：

   - 风险：某些服务器可能限制连接数
   - 缓解：提供配置选项，允许用户调整

3. **磁盘 I/O 瓶颈**：
   - 风险：大量并发写入可能影响性能
   - 缓解：监控磁盘 I/O，必要时降低并发数

### 业务风险

1. **服务器负载增加**：

   - 风险：并发下载可能增加服务器负载
   - 缓解：提供配置选项，根据服务器性能调整

2. **网络带宽占用**：
   - 风险：并发下载可能占用大量带宽
   - 缓解：提供配置选项，允许用户限制带宽
