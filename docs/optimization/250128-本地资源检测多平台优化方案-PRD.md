# 本地资源检测多平台优化方案 - PRD

## 📋 文档信息

- **创建时间**：2025-01-28
- **文档类型**：产品需求文档（PRD）
- **优先级**：高
- **影响范围**：本地资源播放功能、多平台兼容性

---

## 🎯 问题背景

### 当前问题描述

1. **首次播放时未检测本地资源**

   - 用户点击播放后，跳转到播放页面
   - `initAll` 执行获取视频详情，但**没有立即检查本地资源是否存在**
   - 只有在 `updateVideoUrl` 被调用时（选择剧集后）才会检查本地资源
   - 导致即使本地资源已存在，也可能先使用在线资源播放

2. **下载成功后再次播放报错**

   - 下载完成后，资源索引已更新
   - 但路径格式可能不一致（Windows 反斜杠 vs Mac/Linux 正斜杠）
   - 再次点击播放时，路径检测失败，找不到资源
   - 错误信息：`资源路径不存在` 或 `Cannot read properties of undefined`

3. **多平台路径兼容性问题**
   - **Windows**：使用反斜杠 `\`，路径如 `D:\Python脚本\MoonTV\data\videos\...`
   - **Mac/Linux**：使用正斜杠 `/`，路径如 `/app/data/videos/...`
   - **Docker**：
     - 容器内工作目录：`/app`
     - Volume mount：`./data/videos:/app/data/videos`（宿主机路径映射到容器内路径）
     - 环境变量：`LOCAL_STORAGE_PATH=/app/data/videos`（容器内绝对路径）
     - 路径存储：统一使用容器内路径格式（正斜杠），如 `data/videos/新僵尸先生粤语_1992/ruyi_26515`
     - 注意：容器内路径与宿主机路径可能不同，但通过 volume mount 实现数据持久化
   - 当前代码虽然做了路径规范化，但在某些场景下仍可能失败

### 用户影响

- **体验问题**：已下载的资源无法优先使用，需要等待在线加载
- **功能问题**：下载完成后无法播放，需要手动刷新或重新下载
- **兼容性问题**：不同平台表现不一致，影响用户体验

---

## 🎯 优化目标

### 核心目标

1. **立即检测本地资源**

   - 在页面初始化时（`initAll` 完成后），立即检查本地资源是否存在
   - 如果存在，优先使用本地资源播放，避免不必要的在线请求

2. **统一路径处理逻辑**

   - 建立统一的路径规范化机制，确保多平台兼容
   - 在存储、读取、检测三个环节都使用统一的路径格式

3. **优化检测时机**

   - 在多个关键节点检查本地资源：
     - 页面初始化时（`initAll` 完成后）
     - 切换剧集时（`updateVideoUrl` 调用时）
     - 下载完成后（通过 WebSocket/SSE 通知前端刷新）

4. **增强错误处理**
   - 当本地资源检测失败时，提供清晰的错误信息
   - 自动降级到在线资源，不影响播放体验

```typescript
try {
  const localResourceResponse = await fetch(
    `/api/local-resource?source=${encodeURIComponent(
      detailData.source
    )}&id=${encodeURIComponent(detailData.id)}`
  );

  if (localResourceResponse.ok) {
    const localResourceData = await localResourceResponse.json();

    if (localResourceData.exists && localResourceData.metadata) {
      // 本地资源存在，立即切换到本地资源
      console.log(
        `[PlayPage] ✓ 初始化时检测到本地资源，将优先使用本地资源播放`

      // 触发 updateVideoUrl 以设置本地资源 URL

      const episodeIndex = currentEpisodeIndex || 0;
      await updateVideoUrl(detailData, episodeIndex);

      // 设置加载完成状态
      setLoading(false);
      setLoadingStage('ready');
      return; // 提前返回，跳过在线资源设置
    }
  }
} catch (error) {
  // 本地资源检测失败，继续使用在线资源
  console.warn('[PlayPage] 初始化时本地资源检测失败，使用在线资源:', error);

setIsUsingLocalResource(false);
```

### 方案二：统一路径规范化工具函数

#### 2.1 创建路径工具函数

**位置**：`src/lib/path-utils.ts`（新建文件）

**功能**：

- 规范化路径分隔符（统一转换为正斜杠）
- 处理相对路径和绝对路径
- 多平台兼容（Windows/Mac/Linux/Docker）

**实现**：

```typescript
import path from 'path';

/**
 * 路径规范化工具
 * 统一处理多平台路径格式问题
 */
export class PathUtils {
  /**
   * 规范化路径分隔符
   * Windows: \ → /
   * Mac/Linux: 保持不变
   */
  static normalizeSeparator(pathStr: string): string {
    return pathStr.replace(/\\/g, '/');
  }

  /**
   * 规范化路径（统一分隔符，移除多余的 ./）
   */
  static normalizePath(pathStr: string): string {
    let normalized = this.normalizeSeparator(pathStr);
    // 移除开头的 ./
    normalized = normalized.replace(/^\.\//, '');
    // 移除多余的斜杠
    normalized = normalized.replace(/\/+/g, '/');
    return normalized;
  }

  /**
   * 检查路径是否以指定前缀开头（忽略分隔符差异）
   */
  static startsWith(pathStr: string, prefix: string): boolean {
    const normalizedPath = this.normalizePath(pathStr);
    const normalizedPrefix = this.normalizePath(prefix);
    return normalizedPath.startsWith(normalizedPrefix);
  }

  /**
   * 解析资源路径（支持相对路径和绝对路径）
   * @param resourcePath 资源路径（可能来自 index.json）
   * @param basePath 基础路径（storagePath 或 process.cwd()）
   */
  static resolveResourcePath(resourcePath: string, basePath?: string): string {
    // 规范化路径分隔符
    const normalizedPath = this.normalizePath(resourcePath);

    // 如果已经是绝对路径，直接返回
    if (path.isAbsolute(resourcePath)) {
      return resourcePath;
    }

    // 检查是否是相对于项目根目录的路径
    if (
      this.startsWith(normalizedPath, 'data/videos') ||
      this.startsWith(normalizedPath, './data/videos')
    ) {
      return path.resolve(process.cwd(), normalizedPath.replace(/^\.\//, ''));
    }

    // 否则相对于 basePath
    const base = basePath || process.cwd();
    return path.resolve(base, normalizedPath);
  }

  /**
   * 统一存储路径格式（存储到 index.json 时使用）
   * 统一使用正斜杠，相对于项目根目录
   */
  static formatForStorage(absolutePath: string): string {
    const normalized = this.normalizePath(absolutePath);
    const cwd = this.normalizePath(process.cwd());

    // 如果是相对于项目根目录的路径，返回相对路径
    if (normalized.startsWith(cwd)) {
      return normalized.substring(cwd.length).replace(/^\//, '');
    }

    // 否则返回绝对路径（规范化后）
    return normalized;
  }
}
```

### 方案四：在线播放时自动切换到本地 TS 片段（智能混合播放）

#### 4.1 问题描述

**当前场景**：

- 用户正在在线播放视频（使用在线 M3U8）
- 同时，该视频正在后台下载（部分 TS 片段已下载完成）
- 用户需要等待下载完成后手动切换到本地资源，才能享受低延迟播放

**优化目标**：

- 在线播放时，如果下一个 TS 片段已经在本地下载好，自动切换到本地 TS
- 降低播放延迟，提升用户体验
- 实现"智能混合播放"：在线资源 + 本地片段混合使用

#### 4.2 技术方案

**核心思路**：

- 在 HLS.js 的 loader 中拦截 TS 片段请求
- 检查该 TS 片段是否在本地已下载
- 如果已下载，返回本地 TS 片段；否则使用在线 TS 片段

**实现位置**：`src/app/play/page.tsx` - `CustomHlsJsLoader` 类

**实现逻辑**：

```typescript
class CustomHlsJsLoader extends Hls.DefaultConfig.loader {
  constructor(config: any) {
    super(config);
    const load = this.load.bind(this);
    this.load = function (context: any, config: any, callbacks: any) {
      // 拦截 TS 片段请求
      if (
        (context as any).type === 'frag-loading' ||
        (context as any).type === 'key-loading'
      ) {
        const originalUrl = (context as any).url;

        // 检查是否是 TS 片段请求
        if (originalUrl && originalUrl.endsWith('.ts')) {
          // 尝试从本地获取 TS 片段
          this.checkLocalSegment(originalUrl, context, callbacks)
            .then((localUrl) => {
              if (localUrl) {
                // 本地片段存在，使用本地 URL
                (context as any).url = localUrl;
                console.log(
                  `[CustomHlsJsLoader] ✓ 使用本地 TS 片段: ${originalUrl} -> ${localUrl}`
                );
              }
              // 执行原始 load 方法
              load(context, config, callbacks);
            })
            .catch(() => {
              // 检查失败，使用在线资源
              load(context, config, callbacks);
            });
          return; // 提前返回，避免重复加载
        }
      }

      // 其他请求（manifest、level）正常处理
      if (
        (context as any).type === 'manifest' ||
        (context as any).type === 'level'
      ) {
        const onSuccess = callbacks.onSuccess;
        callbacks.onSuccess = function (
          response: any,
          stats: any,
          context: any
        ) {
          if (response.data && typeof response.data === 'string') {
            response.data = filterAdsFromM3U8(response.data);
          }
          return onSuccess(response, stats, context, null);
        };
      }

      // 执行原始load方法
      load(context, config, callbacks);
    };
  }

  /**
   * 检查本地 TS 片段是否存在
   */
  private async checkLocalSegment(
    onlineUrl: string,
    context: any,
    callbacks: any
  ): Promise<string | null> {
    try {
      // 从当前播放状态获取 source 和 id
      const currentSource = this.getCurrentSource();
      const currentId = this.getCurrentId();
      const currentEpisodeIndex = this.getCurrentEpisodeIndex();

      if (!currentSource || !currentId) {
        return null;
      }

      // 调用 API 检查本地 TS 片段是否存在
      const response = await fetch(
        `/api/local-segment?source=${encodeURIComponent(
          currentSource
        )}&id=${encodeURIComponent(
          currentId
        )}&episode=${currentEpisodeIndex}&segmentUrl=${encodeURIComponent(
          onlineUrl
        )}`
      );

      if (response.ok) {
        const data = await response.json();
        if (data.exists && data.localUrl) {
          return data.localUrl;
        }
      }
    } catch (error) {
      console.warn('[CustomHlsJsLoader] 检查本地 TS 片段失败:', error);
    }

    return null;
  }
}
```

#### 4.3 后端 API 实现

**新增 API**：`src/app/api/local-segment/route.ts`

**功能**：

- 接收 source、id、episode、segmentUrl 参数
- 检查本地 TS 片段是否存在
- 返回本地 TS 片段的访问 URL

**实现逻辑**：

```typescript
export async function GET(request: NextRequest) {
  try {
    const { searchParams } = new URL(request.url);
    const source = searchParams.get('source');
    const id = searchParams.get('id');
    const episode = searchParams.get('episode');
    const segmentUrl = searchParams.get('segmentUrl');

    if (!source || !id || !episode || !segmentUrl) {
      return NextResponse.json({ error: '缺少必要参数' }, { status: 400 });
    }

    const storageManager = getStorageManager();
    if (!storageManager.isEnabled()) {
      return NextResponse.json({ exists: false }, { status: 200 });
    }

    // 从 segmentUrl 中提取片段索引
    const segmentFileName = segmentUrl.split('/').pop() || '';
    const segmentIndex = parseInt(
      segmentFileName.replace('segment_', '').replace('.ts', ''),
      10
    );

    // 获取资源路径
    const index = storageManager.readIndex();
    const key = `${source}_${id}`;

    if (!(key in index)) {
      return NextResponse.json({ exists: false }, { status: 200 });
    }

    const indexEntry = index[key];
    let resourcePath = PathUtils.resolveResourcePath(indexEntry.local_path);

    // 构建 TS 片段路径
    const episodeDir = path.join(
      resourcePath,
      `episode_${episode.padStart(2, '0')}`
    );
    const segmentPath = path.join(episodeDir, segmentFileName);

    // 检查文件是否存在
    if (fs.existsSync(segmentPath)) {
      const stats = fs.statSync(segmentPath);
      if (stats.size > 0) {
        // 返回本地 TS 片段的访问 URL
        const localUrl = `/api/local-video?path=${encodeURIComponent(
          segmentPath
        )}`;
        return NextResponse.json({ exists: true, localUrl }, { status: 200 });
      }
    }

    return NextResponse.json({ exists: false }, { status: 200 });
  } catch (error) {
    console.error('[Local Segment API] 检查失败:', error);
    return NextResponse.json({ exists: false }, { status: 200 });
  }
}
```

#### 4.4 优化点

1. **缓存机制**

   - 缓存已检查的 TS 片段状态，避免重复 API 调用
   - 使用 Map 存储：`segmentUrl -> { exists: boolean, localUrl?: string }`

2. **异步处理**

   - TS 片段检查是异步的，需要等待结果
   - 如果检查时间过长（> 100ms），直接使用在线资源，避免阻塞播放

3. **错误处理**

   - 本地检查失败时，自动降级到在线资源
   - 不影响正常播放流程

4. **性能优化**
   - 批量检查多个 TS 片段（预加载）
   - 使用 Web Worker 进行后台检查（可选）

#### 4.5 优势

- ✅ **降低延迟**：已下载的 TS 片段立即使用，无需等待网络请求
- ✅ **无缝切换**：用户无感知，自动使用本地片段
- ✅ **智能混合**：在线资源 + 本地片段混合使用，最佳体验
- ✅ **向后兼容**：不影响现有播放逻辑，失败时自动降级

#### 4.6 注意事项

1. **片段匹配**

   - 需要准确匹配 TS 片段文件名（segment_000.ts）
   - 考虑不同源的片段命名规则可能不同

2. **M3U8 路径解析**

   - 需要从 M3U8 URL 中提取剧集索引
   - 需要处理相对路径和绝对路径

3. **并发控制**
   - 避免同时检查过多 TS 片段，影响性能
   - 优先检查即将播放的片段

## 📝 注意事项

1. **路径格式统一**

   - 存储到 `index.json` 时，统一使用正斜杠
   - 读取时，先规范化路径分隔符再比较
   - 绝对路径和相对路径都要正确处理
   - **Docker 环境**：确保 volume mount 路径与环境变量路径匹配
     - Volume mount：`./data/videos:/app/data/videos`
     - 环境变量：`LOCAL_STORAGE_PATH=/app/data/videos`
     - 容器内路径统一使用 `/app/data/videos` 格式

2. **时序问题**

   - `initAll` 中的本地资源检测是异步的
   - 需要确保 `detail` 状态已设置后再检测
   - 需要处理检测完成前用户切换剧集的情况

3. **性能考虑**

   - 本地资源检测是同步操作（文件系统访问）
   - 避免频繁检测，使用缓存机制
   - 检测失败时快速降级到在线资源
   - **TS 片段检查**：异步处理，避免阻塞播放，超时自动降级

4. **向后兼容**

   - 现有的路径格式（反斜杠）需要兼容
   - 迁移时，逐步规范化现有路径
   - 新存储的路径统一使用新格式

5. **智能混合播放**
   - TS 片段匹配需要准确（文件名、索引）
   - 考虑不同源的片段命名规则差异
   - 预加载检查即将播放的片段，提升体验
   - 失败时自动降级，不影响正常播放
