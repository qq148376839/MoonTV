# MoonTV 下载中心详细进度与可靠并发设计

## 1. 目标

在现有离线下载安全重下能力之上，增加可观测、可暂停、可恢复、可持久续传的下载任务系统，并修复多任务、多分片并发缺少统一调度的问题。

设计目标：

- 下载列表默认显示当前集、阶段、分片进度、速度和 ETA。
- 任务展开后可诊断并发槽、失败分片、重试次数和安全替换状态。
- 所有任务共享一个公平的全局分片并发池，避免多任务成倍放大 NAS 网络和磁盘负载。
- 下载状态和成功分片索引持久化到 NAS，MoonTV 重启后可由用户手动恢复。
- 任一必要文件失败时不提交新版本，继续保留旧播放入口。
- API、SSE 和 UI 不暴露签名 URL 的 query 或 fragment。

## 2. 明确边界

### 2.1 本轮包含

- 下载任务、剧集和分片三级状态模型。
- 全局公平并发调度器。
- 暂停、恢复、取消、取消并清理、任务优先、仅重试失败分片。
- NAS 任务状态和分片索引持久化。
- 重启后的手动恢复。
- REST 摘要、详情和命令接口。
- SSE 增量进度事件及 REST 快照兜底。
- 下载摘要卡、剧集进度面板和分片诊断 UI。
- 并发数配置，默认 8，可配置范围 2–16。
- 对上述能力的自动化测试。

### 2.2 本轮不包含

- 边下边播。
- DASH 下载。
- FFmpeg 转码或封装。
- 浏览器扩展。
- 下载限速。
- 服务启动后自动恢复下载。
- 历史下载目录批量迁移。
- NAS 生产部署。

## 3. 系统边界

系统分为五个职责明确的单元：

1. **下载中心 UI**：消费任务摘要和按需详情，发送控制命令，不自行推断后端状态。
2. **下载控制面**：提供 REST、SSE、任务状态机和命令校验。
3. **全局调度器**：管理所有 TS、KEY、MAP 下载槽位并进行公平分配。
4. **下载执行器**：处理单个剧集的地址准备、广告过滤、分片下载、校验和原子提交。
5. **NAS 状态仓库**：原子持久化任务、剧集、分片索引和私有审计报告。

UI 展示字段必须来自可信的后端状态。UI 不通过轮询间隔、更新时间或百分比反推速度、线程数、失败状态或可播放状态。

## 4. 任务层级与状态模型

### 4.1 层级

- 一个资源下载对应一个任务。
- 一个任务包含一个或多个剧集。
- 一个剧集包含准备项、KEY、MAP 和媒体分片。
- 资源任务展示聚合状态；剧集和分片状态按需加载。

### 4.2 剧集状态

正常状态流：

```text
queued
  -> preparing
  -> downloading
  -> validating
  -> committing
  -> completed
```

辅助状态：

- `pausing`：停止派发新分片，等待当前写入完整结束。
- `paused`：没有活动写入，可安全恢复。
- `partial_failed`：重试耗尽或完整性检查失败，旧入口保持不变。
- `cancelled_resumable`：已取消但保留 generation 和成功分片。
- `recovery_wait`：服务重启后等待用户决定是否恢复。

“是否可播放”不得由进度百分比决定。只有已提交的新版本或仍然存在的旧正式入口可播放。

### 4.3 任务聚合状态

- 全部剧集完成：`completed`。
- 至少一集完成且至少一集最终失败：`partial_completed`。
- 没有剧集完成且存在最终失败：`failed`。
- 存在活动剧集：`downloading`。
- 全部活动剧集已暂停：`paused`。
- 重启后存在未完成剧集：`recovery_wait`。

一集失败不阻止同一资源的其他剧集继续执行。

## 5. 进度、速度与 ETA

### 5.1 单集进度权重

- 地址解析和广告过滤：5%。
- KEY/MAP：5%。
- 媒体分片：85%。
- 完整性校验和原子提交：5%。

媒体分片进度优先按已完成字节 / 预计总字节计算。无法得到总字节时，按已完成分片 / 总分片计算。

资源总进度按各集预计总字节加权。某集无法获得预计大小时，对未知大小的剧集使用等权估算，并在 API 中标记 `progress_estimated: true`。

### 5.2 速度

- 速度以完成写盘的字节为准，不以网络读取字节为准。
- 使用最近 10 秒滑动窗口计算。
- 暂停、等待、校验、提交时速度显示为零或隐藏。

### 5.3 ETA

仅在剩余量已知且滑动窗口中存在足够样本时返回 ETA。以下场景返回 `null`：

- 准备、暂停、等待恢复、校验或提交阶段。
- 最近 10 秒有效吞吐不足。
- 正在发生连续失败或地址刷新。
- 总剩余字节无法可靠估算。

## 6. 全局公平并发调度

### 6.1 并发池

- 默认全局槽位数为 8。
- 配置范围为 2–16。
- TS、KEY 和 MAP 都必须占用同一个全局槽位。
- 任何任务不得通过创建自己的并发限制器绕过全局上限。

### 6.2 公平性

调度器按活动任务轮转派发工作：

- 每个可运行任务至少获得一个槽位。
- 剩余槽位继续按轮转顺序分配。
- “优先任务”在每轮可获得更高权重，但不能提高全局槽位总数。
- 一个剧集进入 `pausing` 后立即停止获得新槽位。

调度队列项至少包含任务 ID、剧集号、分片类型、分片索引、尝试次数和 generation ID。

### 6.3 完成计数

分片只有在文件流完成、文件非空且已通过可用长度校验后才能计入完成。完成、失败和活动计数必须通过单一状态仓库更新，避免并发回调重复累计。

## 7. 重试、地址刷新与失败保旧

### 7.1 重试规则

- 单分片最多尝试 3 次。
- 重试使用指数退避并增加随机抖动。
- 超时、连接中断和 5xx 可重试。
- 内容为空或长度不匹配视为失败并重试。
- 401/403 触发一次剧集地址刷新，再重试尚未完成的分片。
- 已校验成功的分片不得重新下载。

### 7.2 地址刷新后的匹配

刷新播放列表后，使用媒体序号和必要的初始化段关系重建工作项。若新旧播放列表无法安全对应，剧集进入 `partial_failed`，不得混合提交不同版本的分片。

### 7.3 提交规则

TS、KEY、MAP 任一必要文件最终失败时：

- generation 保留为可恢复状态。
- 新播放列表不得切换为正式入口。
- metadata 不得宣称该 generation 已完成。
- 旧播放入口继续保留。
- 用户可执行“仅重试失败项”。

## 8. 暂停、取消、恢复与重启

### 8.1 暂停

暂停命令将剧集设为 `pausing`，停止派发新工作。正在写入的分片允许完成；活动数归零后转为 `paused`。不主动截断正在写入的文件。

### 8.2 取消

默认取消进入 `cancelled_resumable`，保留 generation 和成功分片。

“取消并删除临时数据”必须二次确认，并仅删除未提交 generation 和对应任务状态，不删除正式影片或旧播放入口。

### 8.3 重启恢复

服务启动时加载未完成任务并转为 `recovery_wait`，不自动发起网络请求。

用户点击恢复后：

1. 校验已有成功分片存在且非空。
2. 有可信长度记录时同时校验长度。
3. 将无效文件重新放回待下载队列。
4. 重新获取最新地址。
5. 验证新播放列表与已有分片可安全对应。
6. 继续下载缺失或失败项。

## 9. NAS 持久化模型

建议目录：

```text
<storage>/download-tasks/<task-id>/
  task.json
  episodes/
    01.json
    02.json
```

分片文件继续保存在资源目录的 generation 中。任务状态只保存 generation 引用，不复制媒体文件。

`task.json` 至少包含：

- schema version、任务 ID、资源标识、创建/更新时间。
- 聚合状态、目标集号、优先级。
- 总进度、速度、ETA 和累计写盘字节。
- 各剧集状态摘要。

`episodes/<ep>.json` 至少包含：

- generation ID、阶段和状态。
- 总分片、完成索引、失败索引、活动工作项。
- KEY/MAP 状态。
- 每个失败项的错误分类和尝试次数。
- 可恢复性、刷新次数和最近错误。
- 预计字节、完成字节和进度是否为估算。

所有状态 JSON 使用同目录临时文件写入后原子 rename。公开状态文件不得保存完整签名 URL；完整 URL 继续只允许存在于 NAS 私有审计报告。

## 10. API 与 SSE

### 10.1 REST 摘要

`GET /api/download` 返回任务摘要：

- 任务标识、资源标题、目标集。
- 聚合状态、当前剧集、当前阶段。
- 总进度、速度、ETA、写盘字节。
- 总分片、完成、活动、重试和失败数量。
- 是否可恢复、是否使用轮询兜底。

### 10.2 REST 详情

`GET /api/download/:taskId/detail` 返回：

- 每集状态和阶段。
- 分片聚合及状态区间。
- 当前并发槽工作项。
- 失败项、错误分类、尝试次数和脱敏路径。
- 安全替换状态、旧入口是否保留、广告过滤摘要。

分片状态应使用区间或批量编码，避免为数百个成功分片返回重复对象。

### 10.3 命令

下载命令接口支持：

- `pause`
- `resume`
- `cancel`
- `cancel_and_clean`
- `retry_failed`
- `prioritize`

命令必须验证当前状态，重复命令应保持幂等或返回明确冲突。

### 10.4 SSE

`GET /api/download/events` 推送变化量：

- `task.updated`
- `episode.updated`
- `segment.batch`
- `task.removed`

每个事件包含递增事件序号。客户端断线后携带最后事件序号重连；服务器无法补齐事件时要求客户端重新读取 REST 快照。

SSE 断开不改变任务状态。客户端自动重连，并在不可用时退化为 2 秒 REST 轮询。

## 11. UI 设计

### 11.1 默认任务卡

默认显示：

- 标题、年份和状态。
- 当前集和当前阶段。
- 总进度条。
- 分片完成数 / 总数。
- 10 秒平均速度和 ETA。
- 暂停、恢复或取消等当前有效操作。

### 11.2 展开详情

展开后显示：

- 准备、KEY/MAP、媒体、校验和提交阶段。
- 分片状态图：成功、活动、等待、重试和失败。
- 本任务当前占用槽位及全局总槽位。
- 活动槽当前分片、速度和尝试次数。
- 失败分片、错误分类和重试次数。
- “仅重试失败项”操作。
- 本次地址来源、广告过滤摘要和旧版本保留状态。

URL 只显示脱敏后的域名和路径。

### 11.3 移动端

移动端默认仅显示摘要指标。阶段详情、失败项和操作可在卡片内展开；完整分片状态图和并发槽列表进入二级详情，避免单卡过长。

### 11.4 连接状态

SSE 断开时显示“实时连接已断开，正在轮询”，但不得把下载任务标为失败。恢复 SSE 后移除提示并用快照校准。

## 12. 任务历史与清理

- 已完成任务状态保留 7 天。
- 失败、部分完成和已取消任务状态保留 30 天。
- 清理任务历史不删除正式影片。
- 未提交 generation 的空间占用在 UI 中单独展示，并提供显式清理操作。
- 自动清理只能删除超过保留期且不处于活动、暂停或等待恢复状态的任务记录。

## 13. 自动化验证

必须覆盖：

1. 多任务时活动下载数从不超过全局上限。
2. 公平轮转不会让后加入任务长期饥饿。
3. 优先任务增加权重但不突破全局上限。
4. 暂停停止新分片，活动写入完整结束后才进入 `paused`。
5. 下载流、磁盘写入错误和长度不匹配不会计为完成。
6. 单分片重试次数和退避符合规则。
7. 401/403 只触发一次地址刷新，成功分片不重复下载。
8. TS、KEY、MAP 任一最终失败时旧入口保持不变。
9. 服务重启后任务进入 `recovery_wait`，不会自动请求远端。
10. 恢复时无效本地分片重新入队，有效分片得到复用。
11. 任务、剧集状态文件使用原子写入并能从中断写入中恢复。
12. 阶段权重、字节进度、分片兜底、滑动速度和 ETA 口径正确。
13. SSE 事件有序，断线后能补事件或回退 REST 快照。
14. SSE 不可用时 UI 自动退化为轮询。
15. REST、SSE、UI 和错误文本不暴露 URL query 或 fragment。
16. 摘要卡、展开详情、移动端折叠和操作状态有组件测试。
17. 旧任务和旧下载目录继续显示、播放且不被自动迁移或删除。

## 14. 参考项目借鉴边界

设计参考以下项目的能力划分，而不复制其桌面端架构：

- M3U8 Quicker：持久化完成/失败分片索引、实时速度、失败分片单独重试、可配置并发。
- M3u8Downloader_H：固定线程工作队列、原子完成计数、单分片重试及最终数量完整性检查。

MoonTV 是 NAS 上的 Web 服务，因此采用 REST + SSE、全局公平池和手动恢复，不引入 Tauri、桌面事件总线、插件系统或边下边播。

## 15. 完成定义

设计完成需同时满足：

- UI 可看到本规格定义的摘要和展开细节。
- 多任务、分片、KEY 和 MAP 共享可配置全局公平并发池。
- 暂停、取消、重启和失败路径不产生被误判为完成的文件。
- 重启后可以复用已验证分片并由用户恢复任务。
- 失败分片可以单独重试，完整性失败不切换正式入口。
- REST、SSE、持久化和 UI 的状态语义一致。
- 自动化测试覆盖第 13 节全部验收项。
- 不实现第 2.2 节明确排除的能力，不执行生产部署。
