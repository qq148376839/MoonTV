# 2026-01-19 OrionTV 兼容性资源列表接口修复总结

## 📋 修复背景

通过深入分析 OrionTV 代码发现，OrionTV 的“源不可用/无播放源/换源异常”等问题，根因来自 MoonTV 的 OrionTV 兼容接口在 **资源 key 与实际搜索结果 source 不一致**（以及部分播放链路被认证拦截）。

## 🔍 问题分析（更正）

### 核心问题

1. **MoonTV 搜索功能独立化**：搜索结果的 `SearchResult.source` 来自独立搜索上游返回的真实资源站 key（例如 `789caiji`、`jisu`）
2. **资源列表 key 错误/不一致**：如果 `/api/search/resources` 返回 `official/unofficial` 这类“分类 key”，OrionTV 会把它当成 `resourceId` 调用 `/api/search/one`，从而出现“返回数据不准确/episodes 为空/无法播放”
3. **server-config SourceConfig 为空**：当 `runtime.ts api_site` 为空时，`/api/server-config` 可能返回 `SourceConfig: []`，OrionTV 直接判定“无可用源”
4. **播放链路被认证拦截**：如 `/api/proxy/m3u8` 被 middleware 拦截会返回 401，导致 episodes[0] 拉取失败

### 影响范围

- OrionTV 完全无法使用，显示错误提示
- MoonTV Web 端不受影响（不依赖此接口）
- 所有 OrionTV 用户都遇到此问题

## 🔧 修复方案（最终）

### 1. 修复资源列表接口（返回真实资源站 key）

**目标**：`/api/search/resources[].key` 必须与 `SearchResult.source` 一致（示例：`789caiji`、`jisu`），OrionTV 的 `resourceId` 才能精准定位单源结果。

### 2. 修复认证中间件（放行播放链路）

**问题**：搜索接口需要认证，但 OrionTV 需要在登录前访问

**解决方案**：放行 OrionTV 必需的搜索/播放相关接口：`/api/search*`、`/api/server-config`、`/api/proxy/*`、`/api/local-*`、`/api/image-proxy`、`/api/official-play.m3u8`、`/api/unofficial-play.m3u8`

```typescript
export const config = {
  matcher: [
    '/((?!_next/static|_next/image|favicon.ico|login|warning|api/login|api/register|api/logout|api/cron|api/server-config|api/decrypt|api/search).*)',
  ],
};
```

## ✅ 修复效果

### 修复前

- ❌ `/api/search/resources` 返回空数组或返回 `official/unofficial`（分类 key）
- ❌ `/api/server-config` 返回 `SourceConfig: []`
- ❌ `/api/search/one` 返回不准确数据，或 episodes 为空
- ❌ `/api/proxy/m3u8` 等播放链路被认证拦截返回 401

### 修复后

- ✅ `/api/search/resources` 返回真实资源站 key，且**必须包含 stream 可能返回的非官方源 key（如 `ruyi`）**，否则 OrionTV 会出现“Web 能搜到但 TV 搜不到”
- ✅ `/api/server-config` 的 `SourceConfig` 不再为空且与 resources 一致
- ✅ `/api/search/one` 按 `resourceId` 精确返回对应 `source` 的结果
- ✅ episodes[0] 可直接拉取（非官方通过 `/api/unofficial-play.m3u8` 302 到代理；官方通过 `/api/official-play.m3u8` 302 到真实 m3u8）
