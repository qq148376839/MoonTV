# 2026-01-15 本地资源：混合代理与自动下载修订总结

## 📝 本次修订总结

### 需求与问题

- 本地资源播放在“部分下载/断点下载/切集”场景下不稳定
- 自动下载默认 3 集需要滚动窗口续下（1→1-3，2→2-4，10→10-12）
- 未下载集需要走线上，但希望随着下载推进能“无缝越来越本地”（不应卡顿切源）
- 命中本地后切集不更新 URL、以及“从第 2 集开始下载导致集号错位”等问题

### 已完成的实现与修复

- **自动下载滚动窗口续下**：修复 `episode_range` 真实集号丢失导致的误判/覆盖风险（下载判定与落盘均按真实集号）。
- **缺集不回退第 1 集**：缺集时直接走线上/混合代理，不再错误播放第 1 集。
- **坏集自动回退**：本地播放连续失败时，删除该集 `episode_XX.m3u8` + `episode_XX/` 并更新 index/metadata，然后回退线上播放。
- **混合代理（无缝越来越本地）**：
  - m3u8 重写为 hybrid endpoint
  - TS/KEY 请求本地优先，缺失回源
  - 增加调试响应头 `X-MoonTV-Hybrid-Source: local|upstream`
- **部分下载导致映射错位修复**：metadata 写入改为按全集对齐（占位），并在生成时扫描目录对齐集号；播放本地时优先按 `episode_XX.*` 命名探测，避免历史 metadata 错位。
- **下载中及时“发布”可用性**：下载开始即写 index；每集完成/跳过后实时写 metadata/index，避免“文件已下载但仍认为未下载”。

## ⚠️ 当前遗留问题（待下一轮）

1. **（已解决，2026-01-15）下载 KEY 错集（观测优先）**

   - 根因倾向：上游 key 接口对 `Referer`/防盗链敏感，错误 `Referer` 可能导致 key “漂移/返回默认 key”
   - 已实施：下载器对 KEY 请求强制 `no-cache`，并将 KEY 请求 `Referer` 设为媒体播放列表 URL，同时增加 sha256 指纹日志与“差异覆盖写入”告警（先观测，必要时再升级强门禁）
   - 对应指南：`docs/fixes/260115-本地资源-KEY错集与切源黑屏-修订步骤指南.md`

2. **（已解决，2026-01-15）切换到本地资源黑屏/需刷新，且状态丢失**
   - 根因：非 WebKit 分支 `switchUrl` 未彻底重置 Hls；以及初始化阶段的竞态导致 `updateVideoUrl` 用错 `episodeIndex=0` 且后续不重跑
   - 已实施：切源统一“销毁并重建”播放器与 Hls；恢复进度/倍速/音量/暂停状态；初始化结束后补跑一次 `updateVideoUrl`，避免“显示第 N 集但实际解析/播放第 1 集”
   - 对应指南：`docs/fixes/260115-本地资源-KEY错集与切源黑屏-修订步骤指南.md`

## ✅ 2026-01-16 补充修订（离线中心/下载管理闭环 + 回归修复）

- **离线中心页面**：

  - `/offline/resource`：本地资源详情（剧集列表、单集/整部删除）
- **导航入口**：桌面侧边栏 + 移动端底部导航新增「离线」
- **播放页集成**：
  - 播放器右上角/详情区「下载」入口
  - `EpisodeSelector` 每集状态指示 + 统一状态徽标（未下载/下载中/已下载/失败）

### API 补齐/扩展（支持管理体验）

- `PATCH /api/download`：任务暂停/恢复
- `GET /api/local-library`：本地资源列表
- `GET /api/local-library/detail`：本地资源详情（含每集状态）
- `DELETE /api/local-library/episode`：单集删除（Windows 文件锁重试；失败返回 500 且不写回 metadata）
- `DELETE /api/local-library`：整部删除

### 关键问题修复

- **范围/选集下载集号错位（PRD 16.5.3）**：下载任务按“原始集号”落盘与写入 metadata（避免 10-12 变成 01-03）
- **KEY 防盗链敏感回归防护**：混合代理/回源请求补齐 `Referer` 透传（指向播放列表 URL）
- **“200 但文件未删除”**：修复因重复实现/逻辑分叉导致的假成功；统一 robust 删除逻辑
- **/api/local-hybrid/m3u8 文件异常**：修复同一文件内存在两份实现导致的编译/HMR 不稳定风险（整理为单一实现）
