## 🔍 问题描述

### 1. Windows 路径分隔符问题

**问题**：

- Windows 使用反斜杠 `\` 作为路径分隔符
- 代码中检查路径时使用正斜杠 `/`，导致路径匹配失败
- 结果：已下载的本地资源无法被正确检测，导致重复下载或无法播放

**错误日志**：

```
[StorageManager] isEpisodeDownloaded: 资源路径不存在 - D:\Python脚本\MoonTV\data\videos\data\videos\新僵尸先生粤语_1992\ruyi_26515
```

**根本原因**：

- `index.json` 中存储的路径：`data\videos\新僵尸先生粤语_1992\ruyi_26515`（Windows 反斜杠）
- 代码检查 `resourcePath.startsWith('data/videos')` 失败
- 走到 `else` 分支，使用 `path.resolve(this.storagePath, resourcePath)`
- 导致路径重复：`data/videos` + `data\videos\...` = `data/videos/data/videos/...`

### 2. SSR 阶段的 `undefined.length` 错误

**问题**：

- 服务器端渲染时，某些变量可能为 `undefined`
- 直接访问 `.length` 属性导致运行时错误
- 错误：`Cannot read properties of undefined (reading 'length')`

**影响位置**：

- `urlSource` 和 `urlId` 可能为 `undefined`
- `sourcesInfo` 可能不是数组
- `data.SourceConfig` 可能不是数组
- `preferBestSource` 函数的 `sources` 参数

### 3. Docker 配置路径不一致

**问题**：

- Volume mount：`./data/videos:/data/videos`（挂载到 `/data/videos`）
- 环境变量：`LOCAL_STORAGE_PATH=/data/videos`
- 但应用工作目录是 `/app`，路径不一致

## ✅ 修复方案

### 1. 修复 Windows 路径分隔符问题

#### 1.1 `src/lib/local-storage.ts` - `isEpisodeDownloaded` 方法

**修复位置**：第 219-234 行

**修复前**：

```typescript
if (
  resourcePath.startsWith('data/videos') ||
  resourcePath.startsWith('./data/videos')
) {
  resourcePath = path.resolve(process.cwd(), resourcePath.replace(/^\.\//, ''));
}
```

**修复后**：

```typescript
// 规范化路径分隔符，统一使用正斜杠进行比较（兼容 Windows 反斜杠）
const normalizedPath = resourcePath.replace(/\\/g, '/');
if (
  normalizedPath.startsWith('data/videos') ||
  normalizedPath.startsWith('./data/videos')
) {
  resourcePath = path.resolve(process.cwd(), resourcePath.replace(/^\.\//, ''));
}
```

**修复位置**：第 85-100 行

**修复内容**：

- 在检查路径前，先将反斜杠转换为正斜杠进行比较

#### 1.3 `src/app/play/page.tsx` - 路径处理

## 📌 注意事项

1. **路径规范化**：

   - 所有路径比较前都应规范化路径分隔符
   - Windows 使用反斜杠，Linux/Mac 使用正斜杠
   - 统一转换为正斜杠进行比较

2. **SSR 安全**：

   - 所有可能为 `undefined` 的变量都应提供默认值
   - 所有数组访问前都应检查是否为数组
   - 使用可选链操作符 `?.` 和空值合并操作符 `??`

3. **Docker 配置**：
   - Volume mount 路径应与环境变量路径匹配
   - 使用绝对路径更可靠
   - 确保路径与工作目录一致
